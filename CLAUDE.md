# DSP workbench — заметки для Claude

## Работа с git
- Разработка — в ветке, которую задала сессия; после пуша **всегда создавай PR** (в `main`), даже если не просили.
- Перед созданием PR проверь, что предыдущий PR из этой ветки влит: `list_pull_requests` (head = ветка). Если влит — начни ветку заново от свежего `main` (`git fetch origin main && git checkout -B <ветка> origin/main`), не наслаивай коммиты на влитую историю. Если не влит — допиши в тот же PR, новый не создавай.
- Созданный PR сразу вливай (`merge_pull_request`), но **только свои свежие** — открытые тобой в этой сессии. Чужие и старые PR не трогай. Есть конфликты — сначала слей `main` в ветку и перештампуй (`node tools/stamp.mjs`), потом вливай.
- Коммиты и описания PR — по-русски, коротко, в стиле истории (`git log --oneline`).

## Перед коммитом
- Правил файлы оболочки (`*.js`, `styles.css`, `index.html`, `modules/*`…) — выполни `node tools/stamp.mjs` (версия = хэш файлов, прописывается в `sw.js` и `index.html`), потом `node tools/test-version.mjs`.
- **Версии обязательно повышай, если нужно.** Скрипты/оболочка: `stamp.mjs` (выше) — без него у пользователей останется старый кэш сервис-воркера. Пресеты: правил `presets.js` или состав/параметры пресетов — подними `PRESET_VER`, иначе сохранённые у пользователей пресеты не обновятся.
- **Для каждого нового функционала нужен пресет** в `presets.js` (рабочий пример на готовых блоках, с заметкой-описанием; при необходимости — запись в карту категорий пресетов) + `PRESET_VER`. Без пресета фича не считается готовой.
- Тесты — отдельные скрипты: `node tools/test-<имя>.mjs` (без раннера, DOM не нужен; код модулей грузится через `vm`).

## Офлайн
Приложение — PWA, и всё, что можно, должно работать без сети. Новая фича, которой нужны внешние данные, обязана вести себя так:
- **Небольшое (до пары МБ) и нужное всегда** — файл в репозитории и в `SHELL` (`sw.js`), как `vendor/*.wasm`. Не тяни с CDN: `sw.js` сторонние запросы не кэширует, и на первом запуске без сети всё сломается.
- **Крупное и нужное не всем** (модели, словари, базы) — положи в `vendor/` или `data/` и бери через `OfflineData.blob(имя,[адреса])` (`modules/filestore.js`): файл один раз качается и остаётся в Files → «Offline data». Пути `data/` и `vendor/objdet/` воркер не кэширует (иначе две копии); для новой папки добавь её в проверку в `fetch`-обработчике `sw.js`.
- **Каждый такой ресурс зарегистрируй** для кнопки «⇩ offline» в Files: `OfflineData.fileItem({id,label,mb,auto,files:[[имя,[адреса]]]})` для файлов или `OfflineData.item({id,label,mb,has,get})` для своего хранилища. `auto:true` — только для мелочи (несколько МБ): она докачивается сама через 20 с после старта.
- **Своё хранилище (IndexedDB, Cache API)** — тоже через `item`, чтобы пользователь мог скачать заранее.
- Не дублируй: данные из `OfflineData` не клади ещё и в `SHELL`/IndexedDB, не синхронизируй между устройствами (`meta.offline` пропускает `sync.js`).
- Сетевое (каталоги, API) сохраняй последний удачный ответ и показывай его с пометкой «устарело», а не пустоту; ошибку сети пиши в статус узла.
- Проверка: открой страницу, дождись загрузки, `context.setOffline(true)`, перезагрузи, прогони фичу (см. «Проверка в браузере»).

## Карта проекта
Без сборки: статичный PWA, скрипты подключаются из списка `L` в `index.html`, кэшируются списком `SHELL` в `sw.js`. Новый файл — добавь в оба.
- `core-graph.js` — холст, узлы, провода (`drawWires`, `curve`, `bundleCurves`), выделение, undo, тулбар, дашборд/тайлы.
- `core-engine.js` — движок: топосортировка, обработка блоков, `portsOf`, типы портов.
- `core-dsp.js` — общие DSP-функции; `core-islands.js` — островки/воркеры.
- `modules/*.js` — модули (`def({id,title,cat,ins,outs,params,process,…})`); `*-kernels.js` — чистая логика без DOM (её и тестируют).
- `presets.js` — встроенные пресеты и патчи (при изменении — `PRESET_VER`, см. выше).
- `*-worker.js`, `vendor/` (wasm, библиотеки), `data/` — воркеры, внешнее, данные.
- `tools/android/` — Android-приложение (WebView + foreground-сервис: датчики, камера, Wi-Fi по локальному порту); собирается в Actions (`.github/workflows/android.yml`), логика сервера — `cd tools/android/jvm-test && gradle runTests`. Протокол записей общий с `tools/termux/bridge.mjs`; сторона страницы — `modules/termux*.js`.
- `README.md` — список возможностей по разделам; новую фичу описывай там же.
- Поиск: `grep -n "id:'имя'" modules/*.js` — модуль по id; `grep -n "<id=\"…\"" index.html` — кнопка тулбара.

## Грабли
- **Поля узла.** Модуль не пишет в `n.x`/`n.y` (координаты на холсте), а также в `id, type, p, size, el, ports, out, b, lod`. Состояние держи в своих полях (`n.sx`, `n.buf`…). Иначе в проводах `NaN`, а сохранение портится. Проверка: `node tools/test-nodefields.mjs`.
- **Проверка в браузере.** Playwright и Chromium уже стоят (`require('playwright')`). Статику отдавай через `python3 -m http.server`, не `file://`. Страница один раз перезагружается ради cross-origin isolation — жди `window.crossOriginIsolated===true`. `MOD` — глобальная `const`, а не `window.MOD`. WebGPU в headless: флаги `--enable-unsafe-webgpu --use-angle=swiftshader` (только корректность, не скорость). Сохранение `FileSystemFileHandle` в IndexedDB в headless роняет браузер — проверяй руками.
- **Оптимизации сначала меряй.** SIMD для `leandvb` дал 0.99×, для `mpeg2` 1.20×; WebGPU не выигрывает у FFT на CPU (~0.11 мс на 4096 точек). Выигрыш подтверждай замером до коммита; счётчики — в `core-perf.js` (`Perf`, `Dev`).
- **Пересборка wasm.** `tools/*/build.sh` воспроизводят `vendor/*.wasm` байт-в-байт (проверено на leandvb и mpeg2). Для wasi: `apt-get update && apt-get install wasi-libc libc++-18-dev-wasm32 libclang-rt-18-dev-wasm32`.
- **Service worker.** `navigate()` в `sw.js` намеренно ходит с `no-cache`, поэтому Navigation Preload не включай: он идёт через HTTP-кэш и отдаст старую версию.
- **Узлы холста.** `content-visibility:auto` включается из `cvArm` (`core-graph.js`) после первой раскладки, класс `cvis` на узле, а само свойство — на теле узла `.io3>.mid` (`styles.css`), **не на узле**: paint-containment обрезает и клики, а пины торчат за рамку узла в соседних колонках (на узле клики по выступающей части пина пропадали). Что торчит из самого `.mid`, не должно выходить дальше `overflow-clip-margin:80px`, иначе обрежется.
