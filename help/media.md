# Media

The sample editor and the tracker.

## Sample editor

The **Files** node is a file manager for the browser storage (database *dsp-files*). The root `/` is the *files* storage (anything else, e.g. received over the network); the other storages are system folders in it: *audio* (the sample library: clips stored as float32 WAV), *images* (photos of Table rows and pictures) and *tables* (the Table lists — database *dsp-lists*, every list in its own object store; folders are the `folder/name` prefixes). Make your own folders anywhere, **⤒ import** (or drop files). A click marks a row; **long press**, right click or **Ctrl / Shift + click** starts selecting several (then a tap toggles a row; a folder is marked this way too, a plain click opens it). The action bar appears over the marked items: **✎** rename, **⇢** move, **⧉** copy, **⤓** download, **✕** delete — without a question, an **Undo** note appears instead. Move and copy stay inside one storage. Search by name (current storage), one sort list (name / newest / largest / type). Under the list a **preview** of the selected file: picture, start of a text, waveform of a clip. In *audio*: **▶** plays the selected clip on the `out` port with a progress bar you can drag to seek (inputs `clipId` / `play` / `seek` 0…1, `loop` parameter, outputs `clipId` / `pos`), **✎** opens the clip editor (clips only). **● rec** (or the `rec` input — at 0.5 and above it records, below it stops) records from the `in` port when it is wired and the graph runs, otherwise from the microphone; *record from* can also be the **camera**, the **screen** or **video in** — the picture on the `vid` / `img` inputs (TS → Video, decoders, Camera…; like Record Video, but straight into the store; preset *Digital TV: DVB-T2 → record video to Files*) — video as webm / mp4 as the browser allows, the audio format is *clip* (editable, goes to *audio*), *wav16* or *opus* (microphone). **Receiving**: bytes on the `bin` input (File → Bytes, Bytes → Frames…) are saved as a file (*Received* folder, pictures into *images*; `ok` pulses when saved; *also download* for a copy to disk). The `path` input — `[storage/]folders/[name.ext]`, folders are created — says where a recording or a received file goes (empty: the open folder / *Received*). Any sound file (wav, opus, mp3…) gets the same player in the preview — ▶, seek bar, the `out` port (it is decoded on the first ▶); a video shows in the preview with its own controls and goes to the `vid` output (Video Overlay, Record Video…). This is what the **Sample Library** and **Bytes → File** nodes did — they are gone, old patches open them as Files. Outputs `id` / `name` / `size` of the selected file; **Send selected →** sends every marked file one after another (pulse on `send`, bytes on `bin`; tables go as CSV). Below the list: browser storage meter (free / total / used from `navigator.storage.estimate()`); the first import asks the browser for persistent storage, and an import larger than the free space is refused. Old databases *dsp-samples* and *dsp-photos* are copied into it once with the same ids (patches and Tables keep working) and stay as a reserve; backups include *dsp-files* (old backup files still import).

**File transfer over WebRTC**: *WebRTC Data* opens two channels in one connection — `dsp` (text: Chat, games) and `file` (files, in 16 KB pieces with back-pressure, so a big file does not hold the chat). **Send file…** sends a file from this device; the `sendFile` input takes an id from the Files storage (the Files node's `send` output gives a pulse with the selected file's id when you press *Send selected →*). A received file goes into the *Received* folder of the matching storage (sound → *audio* as a clip, pictures → *images*, the rest → *files*); `file` is its id, `got` a pulse, `progress` 0…1; the readout shows the state. Files over *refuse incoming files over, MB* (200) are declined. Both sides need this version (an older peer has no `file` channel). Preset *Files over WebRTC*.

**Auto-connect and reconnect (WebRTC Data)**: instead of copying codes by hand fill *auto-connect: MQTT broker WebSocket* (`wss://…`, any public or own broker) and *room* (a long secret name, the same on both sides) and tick *auto-connect and reconnect*. The nodes meet in the room, exchange offer / answer through the broker and open the connection; when it drops (or a side reloads the page) they do it again by themselves. Signalling messages are encrypted with AES-GCM from a key derived from the room name and the topic is a hash of it, so the broker sees only noise and a stranger cannot inject an offer without the room name — still, use a long random name. Only the signalling goes through the broker; data flows directly. Needs a secure page (https). The `open` output is 1 while the channel is up; the games take it on `link`: after a reconnect both sides start the game over (the score stays).

**Voice and video (WebRTC Data)**: tick *microphone*, *camera* (*front / rear*) or *share screen* and the track goes into the same connection — together with text, games and files, nothing has to be reconnected. A track can be switched on and off at any time (new offers travel over a service channel inside the connection; both sides may start at once). *mute my microphone* silences without dropping the track, *play the other side* mutes the speaker. The picture of the other side (and your own preview in the corner) is shown inside the node; the `remote` output is a bitmask of what comes in (1 voice, 2 video). Needs https for the microphone and camera; the screen is not shared on most phones. Tracks of the graph's own audio and TV/SSTV pictures are not sent yet. Preset *Call: voice, video, chat and files over WebRTC*; both sides need this version (an older peer has no service channel).

**Sound and picture of the graph over WebRTC** — separate nodes on the wire `rtc` (*WebRTC Data* → `link`): **WebRTC Audio Out** sends a `sig` from its `in` (gain, mute), **WebRTC Video Out** a `vid` (Video file / URL, camera) or `img` (TV, SSTV and any frame; *fps*, *max width*), **WebRTC Audio In** gives the received sound as `sig`, **WebRTC Video In** the received picture as `img` and `vid`. A track has a name (*label*: `voice` / `video` by default): the receiving node takes the track with the same name, so one connection carries as many tracks as you like (several Out nodes with different labels, several In nodes). The microphone, camera and screen of *WebRTC Data* are named `mic`, `camera` and `screen` — *Audio In* with label `mic` gets the other side's microphone into the graph (demodulator, effects, recorder). Tracks come and go on the fly, and return by themselves after a reconnect. The sound is mono at the engine's sample rate with a short buffer (≈0.25 s on send, ≈0.4 s on receive). Preset *WebRTC: audio and video of the graph over a connection*. Turn off *play the other side* in *WebRTC Data* when a received track goes to the graph, otherwise it is heard twice.

The editor fills the screen and plays through its own audio output, no wiring needed:

- **Selection**: drag on the waveform; drag the edge handles to adjust it; tap to place the cursor. Drag on the time ruler or the overview strip to scroll; pinch horizontally to zoom in time, vertically to zoom the amplitude (mouse: wheel zooms, Shift+wheel scrolls, Alt+wheel zooms the amplitude)
- **Zoom** goes down to single samples (dots and stems); the amplitude zoom goes down to one 16-bit step. **✏ draw** redraws samples by hand, e.g. to fix a click
- **Playback**: the selection or from the cursor, with **🔁 loop** (the loop region follows the selection)
- **Edits**: crop to selection, delete, cut / copy / paste (between clips too, resampled when the rates differ), silence, fade in / out, normalize (−1 dBFS, DC removed), gain, reverse. Every edit can be undone / redone (Ctrl+Z / Ctrl+Shift+Z)
- **Spectrogram** (〰): under the waveform or alone, with a frequency scale (linear or log), FFT size, palette and dB range. It is computed for the visible range, so it stays sharp at any zoom
- **Noise reduction by profile**: select a piece with noise only → **noise profile**, then select the part to clean (or nothing for the whole clip) → **apply**. It is a spectral gate on the original samples (reduction, sensitivity, frequency and time smoothing); **preview** listens without changing the clip, **residue** lets you hear what gets removed
- **save** overwrites the clip, **＋copy** saves a new one, **⭳ wav** downloads the selection or the whole clip as 16-bit WAV

Keys: Space play/stop, L loop, Del delete, T crop, Ctrl+A/X/C/V, Ctrl+S save, +/−/0 zoom, S view, ←/→ move the cursor, Esc close.

## Tracker

The tracker is a set of nodes in **Music**, wired by the pink `song` port:

- **Tracker Song** — the song, its sequencer and the channel voices. Open a `.mod`, `.s3m` or `.xm` file, tick **play**. `L`/`R` is the mix of all channels (when they are not wired, it plays straight to the default output). `clk` gives a pulse on every row — wire it to the Drum Sequencer, Piano Roll or Sequencer `clk` and they follow the tracker's tempo, speed changes included. **stereo** is the channel separation, **interpolation** — linear or none (the raw Amiga sound). `row`/`pos` give the current row and position. **✎ Edit** opens the full-screen editor
- **Tracker Instrument** — makes an instrument play a generator of the graph instead of samples: every note of instrument **N**, from any channel, goes to up to 4 voices `freq`/`gate`/`vel` (`freq2`/`gate2`… for the others) — exactly the inputs of Synth (4 voices), Sampler, Acid Bass, Synth (2 osc). Portamento, vibrato, arpeggio are in `freq`, volume effects in `vel`, key off / note cut close the `gate`. While the node is wired, the tracker does not look for samples of that instrument (the list marks it `⇢ module`); the synth's output goes wherever you wire it
- **Tracker Channel** — one channel on its own: `out` (mono, after volume), `L`/`R` (with the channel's panning), and the notes: `gate`, `freq`, `note` (MIDI), `vel`, `inst`. **take out of the song mix** removes the channel from the song's `L`/`R`, so it can go through its own effects
- **Tracker Pattern View** — the live pattern with channel meters; double click opens the editor
- **The editor, panel by panel**: **Tracker: Transport**, **Pattern Editor**, **Pattern Sequencer**, **Instrument List**, **Sample / Instrument**, **Keypad**, **Mixer**. Each shows one panel of the same editing session (cursor, current instrument, octave, undo are shared): put them into dashboard tiles (▦) and you get your own tracker layout. Keys go to the tracker after a click in any of its panels. Preset *Tracker Studio (tiles)* lays them out like Renoise: transport on top, pattern sequencer left, pattern in the middle, instruments right, sample/instrument editor, mixer and the module graph below — switch on ▦ after loading it

Preset *Tracker: Synths as Instruments* plays a bass line on the 303 and chords on the 4-voice synth through two Tracker Instrument nodes, and runs the drum machine from `clk`. *Tracker: Channels through Effects* sends channel 1 through a delay.

The **Sampler** node plays a clip from Files › audio on 4 voices: pick the clip (↻ library re-reads the list), set **root note** — the MIDI note the clip sounds at — and wire `freq`/`gate` from a Tracker Instrument, the piano roll or a MIDI keyboard. In the tracker itself a slot can also take a clip straight from the library (**library…** in the sample panel).

Formats: MOD (M.K./M!K!/FLT4, 2–32 channels xCHN/xxCH, 15-sample Soundtracker), S3M (8/16-bit samples, channel panning), XM 1.04 (instruments with several samples and a note map, volume and panning envelopes with sustain and loop, fadeout, auto-vibrato, 16-bit and ping-pong samples, linear or Amiga frequencies, 1–256 rows per pattern). Each song is saved back in its own format; MOD converts to S3M or XM, S3M to XM.

The replayer follows each tracker's effect rules: MOD/XM 0–F and E-commands, XM G H K L P R T X and the volume column, S3M A–X with the ST3 shared memories (D/K/L, E/F), fine and extra fine slides, note cut/delay, pattern loop and delay, retrigger, tremor, key off. It was checked against libxmp tick by tick on its test modules.

**Editor** — full screen (**✎ Edit**) or the panel nodes above. Edits are heard right away and are kept in the browser (IndexedDB) together with the patch; **⭳** downloads the song as a regular module file.

- **Pattern**: the cursor row stays in the middle. Arrows move, Tab / Shift+Tab jump between channels, PgUp/PgDn by 16 rows, Home/End. Mouse: click places the cursor, drag selects a block, wheel scrolls (Shift+wheel — channels). Touch: tap places the cursor, drag scrolls
- **Entry**: **Enter** toggles edit mode (red cursor). The keyboard is a piano in the FT2 layout (Z S X D C… — lower octave, Q 2 W 3 E… — upper), physical keys, so it works with any layout; `1` or `` ` `` enters key off (XM) / note cut (S3M). F1–F8 or numpad +/− set the octave, **step** is how many rows the cursor goes down after a note. Instrument and parameter columns take hex digits (S3M instrument and volume — decimal), the effect column — 0–F for MOD, 0–9 and A–Z for XM, letters for S3M. The XM volume column: 00–40 is the volume, 6x–Fx are commands (slides, vibrato, panning, portamento). The status line explains the effect under the cursor
- **Block**: Shift+arrows or mouse drag select, Ctrl+A selects the channel (twice — the whole pattern), Ctrl+C/X/V copy / cut / paste, Del clears, Ctrl+↑/↓ transposes by a semitone (with Shift — by an octave), Insert / Backspace insert / delete a row in the channel. Ctrl+Z / Ctrl+Shift+Z — undo / redo of every edit
- **Channels**: click a channel header to mute it, double click — solo; `⇢` marks a channel taken out by a Tracker Channel node
- **Song** tab: order list (tap a position to edit its pattern), insert / delete positions, change the pattern at a position, new / clone / clear pattern, pattern length (XM), channels, initial speed / tempo, global volume, restart position, linear frequencies (XM)
- **Samples** tab (**Instruments** for XM): name, volume, finetune (MOD/XM), C-4 rate (S3M), panning and relative note (XM), loop off / forward / ping-pong; drag on the waveform to set the loop, ▶ plays the sample. **load** (or drop an audio file on the tracker) imports any audio file — for MOD resampled to play at its own pitch on C-3, for S3M/XM kept at its rate and tuned to C-4; **✎ edit** opens it in the [sample editor](media.md#sample-editor), **save** there writes it back. XM instruments: several samples, the note map (tap or drag over the keys to give them the selected sample), volume and panning envelopes (drag points, double click adds one, **sus** / **loop** at the selected point), fadeout, auto-vibrato
- **Keys** tab / Keypad — the same on screen for phones: two-octave piano, hex and letter pads, key off, cursor keys, block operations
- **Mixer** tab / node — per channel: level meter, volume, panning, mute, solo (volume is kept with the song in the browser; the formats have no place for it)
- Space plays the song from the current position, Shift+Space loops the current pattern from the cursor row; **⇣ follow** keeps the cursor on the playing row


### Music

- Synths (2 osc, 4 voices), acid bass (303), drum sequencer, Files › audio (sample library) with an audio editor (see [Sample editor](media.md#sample-editor))
- **Tracker**: plays and edits MOD (ProTracker), S3M (Scream Tracker 3) and XM (FastTracker 2); split into graph nodes: song, single channels, instruments played by your own generator modules, pattern view, and every editor panel as its own node — lay them out in dashboard tiles as your own Renoise-style editor (see [Tracker](media.md#tracker))
- **Sampler**: polyphonic (4 voices) player of clips from Files › audio, pitched by `freq` — plays from the tracker, piano roll or MIDI
- Piano roll, step sequencer, generative melody, arrangement playlist, master clock
- **Studio** is a set of ordinary graph nodes and wires; there is no separate studio. Data lives in the nodes, editors live inside the nodes, everything is wired (`modules/studio-*.js`; data and presets in `studio-kernels.js`, block DSP in `studio-dsp.js`, `node tools/test-studio.mjs`, `node tools/test-studio-dsp.mjs`).
  - **Song (Studio)** holds a composition (patterns, channels, playlist, mixer), **loads** it (8 example songs, Files › Songs, a `.json` file) and **saves** it (💾 Files › Songs, `⬇ .json`); the pin `song` (its own port type) goes to the blocks that depend on the composition. They edit the shared song, the node keeps it; the other blocks refresh by themselves. Without the `song` wire a block works on its own data.
  - **Pattern Playlist (Studio)**: pattern blocks on 8 lanes; lane k gives `gK` (a clip is playing) and `pK` (its pattern index, `-1` while no clip plays — one wire to a Drum Machine / Piano Roll `pat` and to the Mixer `scene`), `bar`, `step`, `end`, loop region; `clk` / `run` / `reset` in.
  - **Drum Machine (Studio)**: step grid, steps on `clk` (Master Clock) or its own bpm, `pat` picks the pattern (negative = silent), a gate pin per row `g1…g8` (a trigger for a Sampler or any gate input), built-in drum sounds and clip rows (a sample from Files › audio) on `L` / `R` / `out`, swing, gate length. With `song` it plays the drum rows of the song.
  - **Piano Roll (Studio)**: the full piano-roll editor, patterns, `clk` / `run` / `reset` / `pat`, outputs `freq / gate / vel` ×4 like the classic Piano Roll; with `song` the parameter *channel* picks which channel of the song it edits and plays.
  - **Mixer (Studio)**: 16 strips (inputs `in1…in8`, the others for buses), level / pan / mute / solo, per-strip FX chain, sends between strips (strips 14 / 15 are the reverb and delay buses in the example songs), master FX, `g1…g8` gate inputs, **scenes** (the `scene` input takes a pattern number; the field under a strip lists the numbers where it sounds, `1,3-4`) and a **sleep timer** (minutes, then a fade-out in seconds; `left` shows what remains). With `song` its strips are the song's inserts.
  - **Effects as nodes**: *EQ, Compressor, Filter, Distortion, Bitcrusher, Chorus, Phaser, Delay, Reverb, Pump (sidechain), Trance Gate, Stereo Width* (Audio) — inputs `L` / `R`, outputs `L` / `R`; Delay, Pump and Gate follow `clk` or `bpm`.
  - Presets: *Studio: Drum Machine → Sampler*, *Studio: Playlist → Piano Roll → Synth*, *Studio: Sleep Mixer*, *Studio: Arranged Song (one wire per lane)*, *Studio: Effects Chain*, and eight *Studio Song: …* (techno, trance, deep house, drum & bass, acid, dubstep, lo-fi, ambient) built as Song + blocks + synths + Mixer.
- MIDI keyboard input, ADSR envelope
- **Winamp** (Music; no skins): **Music Player (Winamp)** plays one track — play / pause / stop, seek, volume, balance, speed, elapsed / remaining time, kbps / kHz / mono / stereo, stereo `l` / `r` outputs plus `pos`, `time`, `playing`, `end`, `title`; keys **Z X C V B** while it is focused; the next track is decoded in advance, so tracks follow without a gap. The track list is a separate, reusable node **Playlist** (`modules/playlist.js`): it keeps the list in the patch, with shuffle / repeat off / all / one and drag-to-reorder, and wires to a player — `fs` / `url` / `name` / `go` / `nfs` / `nurl` go to the player, `next` / `prev` / `end` / `req` / `playing` come back. Files live in the shared file storage (the same as **Files** and the Sample Library): **files** puts a copy into *Files → Music* (or into the library as mono clips — the *→ Samples* choice), **library** picks from the file manager, files can be dragged from a Files node onto the playlist or sent by wire (`add` ← Files `send`). URLs and **Internet Radio** stations (`url` + `name` wires, or all found stations from Internet Radio's `stations` output (every station, with or without coordinates) into `rows` with the **stations** button) play as streams through `<audio>`, like Audio Stream. **Media Library** (`modules/medialib.js`, logic in `modules/medialib-kernels.js`, `node tools/test-medialib.mjs`) is the tree of the classic Winamp library: *Local files* (Music — the *Music* folder of Files, Recently added, Artists, Albums, from the ID3 tags) and *Network services → Internet Radio* (stations from the `rows` wire). A click on a category puts its tracks on the `list` output, a double click also pulses `play`; wire `list` → Playlist `set` (replaces the list) and `play` → Playlist `req`. **Graphic Equalizer (10 bands)** (Audio) — Winamp's bands 60 Hz … 16 kHz, preamp, 16 presets, response curve, double click a slider to zero it. Presets *Winamp* (library + player + playlist + equalizer + Radial Spectrum / Spectrum Bars; the ▦ view lays them out like the classic Winamp) and *Winamp: Internet Radio Playlist*. Logic: `modules/player-kernels.js`, `node tools/test-player.mjs`
- **Band FFT (few bins)** (Processing): an FFT that outputs only 4…128 bands (log / mel / linear scale, tilt dB/oct, fall time) as a `spec`; also `bass` / `mid` / `treble` / `level` (0…1), a `beat` pulse and the tempo `bpm` (median of the beat intervals)
- **Visualizers**: **Spectrum Bars** (Analysis; styles bars / round / led / mirror / line, peak markers; takes Band FFT or a plain FFT and groups it into bars itself) and, in Music, **Radial Spectrum** (rotating circle, bass pulse, flash on the beat), **Neon Waveform** (triggered line, ring, XY / Lissajous), **Beat Particles** (burst on the beat, fountain by bands, warp flight) and **Ridgeline Spectrum** (the "Unknown Pleasures" 3D history). Presets in *Music: Visualizers*. Logic: `modules/viz-kernels.js`, `node tools/test-viz.mjs`
  - Ridgeline **rf mode** is a 3D waterfall for the air: the whole source span with absolute frequencies, the maximum of the bins per column (narrow carriers are kept), a frequency axis and dB legend, `fpeak` output and the peak in the readout — feed it an FFT / spectrum from a USB SDR or tinySA (preset *Ridgeline Spectrum: Air History (RF mode)*)

### Output & extensibility

- Sound card output (per-node output device selection, peak/clip meter), WAV / MP3 recording (files named by date and time; optionally streamed straight to a disk file, so the length is not limited by memory — Chrome/Edge), log to a [Table](data.md#table), trigger recorder (modes manual / **gate** — records while `trig` is high, e.g. the receiver's `sqOpen`, plus *post-record* time after it closes / level / edge; *tag* goes into the clip name)
- Sound card output (per-node output device selection, peak/clip meter), WAV / MP3 recording (files named by date and time), log to a [Table](data.md#table), trigger recorder
- **Network Out**: WebSocket (`ws://`, `wss://`, reconnect) — text on change, numbers as a JSON object every period, or mono PCM16 audio (a JSON header first, then binary blocks). Example: `websocat -s 8765` on the receiving side
- **Map** (offline vector base map, OSM / satellite / relief tiles and overlays, GeoJSON / KML / GPX layers, tracks, markers — see [Map and records](map.md#map-and-records)), screen transmitter, indicators
- **Beep** (Output): a `go` pulse plays a short tone through its own audio context (independent of the engine; the browser allows sound only after a tap on the page). Pitch (the `freq` input overrides), length, number of tones in a row and the pause between them, volume, wave, *min gap between beeps*; **Test** plays one. Used in the preset *Object Detect: Camera Video and Photo* (a beep on every new object).
- **Vibrate** (Output): a `go` pulse vibrates the phone (Vibration API) for *duration* or the `ms` input; *pattern* (`200 100 200`, ms) makes a series. Android Chrome / Firefox only, the page needs a tap first
- **Notify**: speaks a text aloud (speech synthesis), shows a system notification and/or vibrates — on a new text or a `go` pulse, with a minimum gap between alerts (e.g. a decoded message or a CFAR detection → voice alert)
- **MQTT Out**: publish text or a number (template `{v}` / `{v:N}`) on change; topic from a parameter or a wire, QoS 0/1, retain. Example — an IR blaster on Tasmota: *IR Encode* (output format «tasmota mqtt») → MQTT Out `cmnd/<device>/IRsend`
- **Serial Out (WebSerial)**: write text or a numeric value to a serial port — Arduino, relays, transceiver CAT control (template `FA{v:11};` turns a frequency into a Kenwood command); device replies come back on the `reply` output
- **HTTP Out**: webhook request (POST / PUT / GET, custom headers) — text on change, or numbers as a JSON object on a `go` pulse or every period. The server must allow CORS, and from the https demo only `https://` (or localhost) works
- **MIDI Out** (Web MIDI): `gate` → note on/off, `note` (or `freq` in Hz straight from *MIDI Keyboard*) with velocity, and a `cc` input for control change — drive hardware synths and a DAW from any signal
- **Firmware flashers** (WebSerial, Chrome/Edge): **Flasher: Quansheng UV-K5** **Flasher: Radtel RT-880** and **Flasher: Radtel RT-890** and **Flasher: Radtel RT-4D** — see [Firmware flashers](protocols.md#firmware-flashers)
- Module Builder and Script nodes for writing custom DSP code in the browser
