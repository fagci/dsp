# Processing and interface

IQ blocks, control logic, indicators, themes, dashboards and tiles.

## IQ blocks

A wire of the **IQ** type (lime) carries a stream at its own sample rate: each engine block it brings as many samples as the source produced since the previous block (none, one chunk or several), together with the stream's sample rate and center frequency. So a chain can run at 2.4 MS/s next to audio at 48 kHz, and a receiver is wired from blocks instead of being hidden inside the SDR node.

- **IQ Generator** — a test signal (carrier, AM, FM, **WFM stereo** with a pilot and RDS station name — the tone in the left channel only, to check separation — USB, LSB, **ADS-B** — DF17 frames from three simulated aircraft, **LRPT** — Meteor-M CCSDS frames with an MSU-MR test picture, OQPSK + NRZ-M or QPSK, **RS41** — a radiosonde going up, **STD-C** — an Inmarsat-C TDM carrier with EGC warnings, **MPT1327** — a control channel with test codewords, **AIS** — four vessels, a base station and a buoy: GMSK 9600 Bd position and static reports, **POCSAG** — a text page, a numeric page and a tone-only call at 512 / 1200 / 2400 Bd, **DCF77** / **WWVB** — the carrier with the power dips of the current time, **ISM433** — OOK or 2-FSK telegrams of a Nexus-type sensor, an EV1527 remote and an unknown Manchester packet, **DMR** — a repeater downlink with a voice call, CSBK and text messages, or a mobile uplink / direct-mode signal, **4FSK** — a test transmitter per digital voice protocol: P25 voice and control channel, NXDN, YSF, M17, D-STAR, dPMR, **TETRA** — a test cell: sync burst, control channel with addresses and messages, a call in slot 2, **GSM** — a BCCH carrier: FCCH, SCH, System Information, **ACARS** — test messages, **Analog TV** — a PAL / NTSC test card, FM or AM, at 8–20 MS/s) at an offset from the center, plus noise; sample rate up to 2.4 MS/s (up to 20 MS/s for Analog TV). *clock error, ppm* simulates a source whose clock differs from the sound card
- **USB SDR → `iq`** — the raw IQ at the native rate (live or from IQ file playback); samples of the old frequency after a retune are not passed on. The USB buffers go on as they are (8 or 16 bit) and are turned into floats by whoever reads them — for an IQ chain in a worker that happens in the worker, not on the main thread
- **IQ Frequency Shift** — brings `freq` (absolute Hz, e.g. marker `f1` of a Spectrum Analyzer) or center + *offset* down to 0 Hz
- **IQ Decimator** — windowed-sinc FIR (Blackman) and decimation by 2…64; *cutoff* is a fraction of the output rate. Works on complex and real streams
- **IQ Interpolator** — the reverse: raises the sample rate by 2…64 (zero-stuffing + polyphase FIR, gain compensated), the centre frequency is unchanged; *cutoff* is a fraction of the input rate (images are about −70 dB). Use it to feed a narrow band to a wideband sink: *IQ file → Frequency Shift → Decimator → … → Interpolator → Frequency Shift → HackRF TX* re-transmits one cut-out channel (HackRF TX needs ≥ 2 MS/s, so e.g. 48 kS/s × 50 = 2.4 MS/s). The shifts set the air frequency: the stream centre `fc` is what HackRF tunes to, the signal sits at its offset from it
- **AM/FM/SSB Demodulator** (`iqDemod`) — everything the USB SDR's own demodulator does, as a block. `out` is the audio as a real stream, `stereo` a complex one (re — left, im — right; mono duplicated), so IQ → Audio gives L on `out` and R on `q`
- **Sound in the same demodulator and modulator** — *AM/FM/SSB Demodulator* has an `audio` input too: a signal from the audio band (an SSTV / FAX subcarrier, an SSB voice at 1.5 kHz, a tone-modulated carrier). The node itself moves the carrier *freq* to zero and filters (*channel width*; for SSB — the bandwidth), then demodulates as usual; the `audio` output gives the result as a plain signal, so no adapter nodes are needed. FM deviation *dev* sets the scale (±1 at ±dev); *remove DC* off keeps the level of baseband data and images. *AM/FM/SSB Modulator* with *sample rate = audio* does the opposite: the carrier *offset* is in the audio band and the `audio` output is the modulated signal. The old *AM/FM/SSB Demodulator* (`demod`) node is gone; old patches are converted on load.
  - **FM** — deviation, 50/75 µs de-emphasis
  - **WFM** — 75 kHz; stereo from a PLL on the 19 kHz pilot (switched in smoothly when locked), **RDS**: station name and radiotext on the `ps` / `rt` outputs and in the readout; audio low-passed at 15 kHz and decimated to ≥ 40 kS/s. Feed it ~150–260 kS/s
  - **AM** — with AGC the output is the modulation depth (level does not depend on signal strength)
  - **SAM** — synchronous AM: a PLL on the carrier (wide to acquire, narrow when locked, holds phase through fades), coherent detector; sideband both / USB / LSB / **ISB** (upper → left, lower → right on `stereo`). `lock` output, carrier offset in the readout
  - **USB / LSB** — Weaver, 8th-order filter, peak AGC (instant attack, 0.3 s hold, 0.4 s release)
- **IQ DC Block** — removes the LO spike of zero-IF receivers from I/Q
- **IQ Noise Blanker** — blanks short impulses (ignition, switching supplies) on the wide band before the channel filter, where they are still short
- **IQ Squelch** — RSSI (dBFS) and SNR over a tracked noise floor; opens by SNR or level with 3 dB hysteresis and a hang time, fades in/out in 5 ms; `rssi`, `snr`, `open` outputs
- **Modulation Meter** (`modMeter`), **IQ Quality** (`iqQuality`) and **Signal Meter** (`sigMeter`) — instruments on an `iq` wire, see [Measuring instruments](analysis.md#measuring-instruments)
- **I/Q → IQ** — two engine signals (e.g. the stereo line input from a receiver with an IQ output, or Hilbert I/Q) into an IQ stream; IQ → Audio does the reverse. For a sound card: Microphone (A+B) in *stereo device* mode (up to 192 kHz; the engine rate at the top sets the band) → I/Q → IQ → IQ Balance
- **IQ Balance** — fixes the I/Q mismatch of sound-card and direct-conversion receivers (the mirror image): Q gain and phase, *auto* (blind, from the I², Q², I·Q averages — needs a spectrum symmetric on average: noise, a busy band) or manual, plus a fractional Q delay (channel skew, often ±1 sample on sound cards). The readout shows the estimate and the image level before → after (1 dB / 5° → about −23 dB, corrected below −50 dB)
- **Auto Notch (NLMS)** (Processing) — removes steady whistles and heterodynes from audio; `tones` is what was removed
- **IQ → Audio** — the bridge into the engine's audio: ring buffer and a cubic resampler to the sound card rate. The source clock (SDR, file) and the sound card drift apart; the read rate follows the buffer within ±2000 ppm, the readout shows the buffer and the correction. **buffer** is the minimum kept: data comes in bursts (worker, USB), so the bridge watches the lowest fill over 0.5 s, not the average. One second after start the excess that was in flight while a worker spun up is dropped at once instead of being drained slowly with a pitch offset. Decimate to about the audio rate before it: the bridge has no anti-alias filter
- **IQ Spectrum** — spectrum of a stream, one FFT over the latest N samples per update (*update, ms of signal*, 16 by default) with exponential smoothing over *smoothing, frames* (absolute frequencies for complex streams) for the Spectrum Analyzer
- **IQ Channelizer** — a polyphase filter bank: cuts the stream into N channels (8…1024) spaced sr/N with one FFT for all of them, so many signals can be received at once. Each channel comes out at sr/N (**oversampling 1**) or 2·sr/N (**2**: flat to the channel edge, no aliasing there; with 16 taps per channel the neighbour's centre is rejected by more than 60 dB). **outputs** (1…8) are slots: **manual** — the channels of the listed frequencies (or `f1…` inputs), **strongest** — the strongest active channels above the noise floor (median of the channel powers) + threshold, one slot per signal peak, held for **hold** seconds after it goes quiet; the centre channel (DC spike) is skipped. `spec` is the power of every channel, `active` — how many slots are busy. About 15% of a core at 1.024 MS/s (64 channels, 2× oversampling, 16 taps) — in its worker The polyphase filter runs as a WebAssembly SIMD kernel (`tools/simd/poly.c`, built into `modules/simd-kernels.js` by `tools/simd/build.sh`, which needs only clang's wasm32 target); a browser without WASM SIMD falls back to the same filter in JavaScript, result identical to 1e-5. Load at 2.4 MS/s on one core, share of real time: N = 64 / 256 / 1024 — 0.28 / 0.31 / 0.40 (JavaScript: 0.84 / 0.83 / 0.79)
- **One `iq` pin instead of I and Q** — the modules that took or gave a pair of signals now have a single `iq` pin: *Constellation*, *Zoom-FFT (I/Q)*, *Magnitude/Phase*, *PSK Slicer*, *Symbol Sync*, *HFDL: Symbol Sync*, *HFDL: Symbol→Bits* (inputs) and *AM/FM/SSB Demodulator*, *Carrier Acquisition*, *Quadrature Shift*, *Hilbert Transform*, the synchronizers' symbol outputs (outputs). A wire from any `iq` source (USB SDR, IQ blocks) goes straight to it; the node gets I and Q at the engine rate through the same bridge as *IQ → Audio* (decimate to about the audio rate before it — the bridge has no anti-alias filter), and its own I/Q come out as an `iq` stream like *I/Q → IQ* does. The old I and Q pins are hidden until a wire is connected to them, so saved patches and presets keep working unchanged and still show their wires; a wire on I / Q wins over `iq`
- **Auto adapters** — wiring `iq` to a signal pin (or a signal to an `iq` pin) in the editor inserts the converter by itself: *IQ → Audio* for `iq` → signal, *I/Q → IQ* for signal → `iq`. A pin named `Q` / `q` goes to the second channel, any other to the first; a second wire from the same source reuses the adapter. So one `iq` pin is enough on a module, no separate I and Q pins
- **Symbol chain** — the 4FSK receiver taken apart into blocks (the same path *Digital Voice Decoder* runs as one piece). Symbols travel on an IQ wire as a real stream at the symbol rate, levels about ±1, ±3 (dibit 00 → +1, 01 → +3, 10 → −1, 11 → −3):
  - **FM Discriminator** — IQ → frequency in Hz (channel filter cutoff, slow DC block); a real input is taken as FM audio
  - **RRC Matched Filter** (`symRrc`) — baud and roll-off α
  - **Symbol Slicer (4-level)** — samples at the symbol rate with cubic interpolation; the timing follows the symbol energy (maximum at the sampling instant, early / late samples at ⅛ symbol), the level from the mean |y|
  - **Symbol Sync Search** (Protocols) — several sync words at once (hex, separated by spaces); a candidate is a window whose correlation with the word is at least *minimum correlation*, then gain and offset are fitted on the word (the sign of the gain is the polarity — an inverted spectrum is turned back) and *tolerance* bits may differ. The frame (*length* symbols after the word) goes out on `blk` as ±1 soft bits (`d`, like Sync Word → Frame; feeds Block Viewer, CRC, Scrambler, Interleaver, Viterbi) plus dibits (`dib`), the word, polarity and error count. Words that are inverses of each other (M17 LSF 55F7 / stream FF5D) are told apart by the polarity-first rule
  - **Frame grid in Symbol Sync Search** (advanced parameters): *symbols before the word* (the frame starts earlier than the word — DMR 66), *frame period* (after a lock a frame goes out every *period* symbols, also where the word is missing — DMR voice bursts B–F — the word is looked for ±1 symbol from the expected place, with a looser *error tolerance while the grid is held*, and *frames without the word before the lock is dropped*) and the whole frame on `blk` (`fr`, with `at` = the word's position, `hit`, `outer`). *timing loop gain* of the slicer is 0.05 by default (DMR's α = 0.2 needs a faster loop than 0.01)
  - **Protocol Decoder (4FSK)** (`fskSym`, Decoders) — the other 4FSK protocols (P25, NXDN 9600 / 4800, YSF, D-STAR, dPMR; also DMR and M17 in one piece) on a chain of blocks: its input is the output of *RRC Matched Filter* (a real stream at any rate ≥ 2 × baud; no Symbol Slicer in front of it), and it runs the protocol code of *Digital Voice Decoder* unchanged — 8 clock phases per symbol, the best phase and the levels from a fit on the sync word, frame grid, NID / LDU / TSBK / CAC / headers, records and raw vocoder frames. These protocols have narrow eyes (α = 0.2, strict limits on sync-word errors and fit residual), and a blind timing loop in front of them loses frames; choosing the phase by the data is what the single node does and what this node does. `protocol` picks one, `auto` — every protocol with the symbol rate in `baud`. **Expand into blocks** now works for every protocol: `IQ Decimator → FM Discriminator → RRC → Protocol Decoder` (M17 and DMR keep their longer chains). Preset **P25: Receiver Built from Blocks (Generator)**. Checked on all 17 generator signals (P25 ×4, NXDN 9600 ×3, NXDN 4800 ×2, YSF ×2, D-STAR ×3, dPMR ×2): the same records and vocoder frames as the single node
  - **DMR Frame Parser** (Decoders) — `blk` from a Symbol Sync Search with the DMR chain → `rec` and `voice` (raw AMBE+2): the channel layer of *Digital Voice Decoder* with `proto = dmr` (CACH / Short LC, slot type, EMB, BPTC, Reed-Solomon, CRC, LC, CSBK / MBC, data, SMS). Polarity comes from the FEC (voice and data words are inverses of each other): at once from a data frame with a correct slot type, otherwise from two frames in a row that agree on polarity and colour code; an idle TDMA slot (an unmodulated carrier, which slices into a constant pattern that is a valid EMB of CC 0 once flipped) is dropped by the share of outer levels. **Expand into blocks** works for `proto = dmr` too. Preset **DMR: Receiver Built from Blocks (Generator)**. On the generator's DMR signals — repeater, mobile and both direct-mode slots, clock error 0–300 ppm — the chain decodes every call, end and alias, and for the repeater the same CSBK, data headers and messages as the single node (a few more of them)
  - **M17 Frame Parser** (Decoders) — `blk` from Symbol Sync Search → `rec` (call, end, packet / SMS, BERT) and `voice` (raw Codec 2 frames): the same channel layer as *Digital Voice Decoder* with `proto = m17` (de-randomizer, interleaver, convolutional decoder, Golay, CRC, LSF reassembly from LICH), without the physical layer. The frame type comes from the sync word (55F7 LSF, FF5D stream, 75FF packet, DF55 BERT)
  - preset **M17: Receiver Built from Blocks (Generator)**.
  - **Any data over a 4FSK channel (not any standard)** — **Data → Symbols (universal)** (Protocols; `dataTx`) takes a camera / video / image frame (`img`, encoded to JPEG at the chosen width and quality), a file, text or a bit block, cuts it into fixed frames (sync word, number, total, length, up to 255 payload bytes, CRC-16, body whitened with PN9) and sends them as `blk` with dibits at the pace of the symbol rate: *Send* or `go`, *repeat* for a stream of frames. It goes to **Symbol Player** → **RRC Pulse Shaper** → **FM Modulator**, so the sync word and the rate can be those of DMR (default `755FD7DF75F7`, 4800 Bd) but the content is not DMR. **Symbols → Data (universal)** (Decoders; `dataRx`) is the other end: `blk` from Symbol Sync Search (the same word, `len` = (payload + 7) × 4 symbols) → CRC check, reassembly → `text`, `img` (a JPEG / PNG is shown as a picture), `rec`, progress, *Save last data*. No error correction beyond the CRC (a frame with a wrong CRC is dropped, there is no retransmission); 4 levels only. A long lead-in precedes the first frame (the slicer levels settle) and each frame ends with a short tail. *Symbol Sync Search*, the builders and *Symbol Player* also pass the frames of the last second or two in `blk.all` (consumers drop what they have already taken by `id`), so frames sent back to back are not lost when the worker runs faster than the main thread. Checked in headless Chromium through the whole chain without a radio (text in 3 frames, a 64×48 JPEG in 5 frames, CRC always good); a real camera, a real radio and a DMR receiver have not been tried. Preset **Data over 4FSK: Image, File or Text (Loopback)**.
  - **Data in real DMR frames** — **DMR Data Builder** (Protocols; `dmrTx`) takes the same sources (camera / video / image frame as JPEG, a file, text, bits), cuts them into datagrams (number, total, length, CRC-16; up to 255 bytes) and sends each as an **UDP / IPv4 packet in a DMR data call**: an optional CSBK data preamble, the data header (CRC-16), blocks of rate ½, ¾ or 1 with CRC-32 (BPTC / trellis), slot type with the colour code, the data sync word of the chosen mode, and in *repeater* mode the CACH with the Short LC. Modes: repeater downlink (two slots, the other one idle), mobile uplink, direct TS1 / TS2; radio IDs, group call, UDP port are parameters. Output `blk` goes to **Symbol Player** → **RRC Pulse Shaper** (α 0.2) → **FM Modulator** (648 Hz). **Digital Voice Decoder** (DMR) reads it as an ordinary data call (the preamble, the header, `UDP <port>`, `crc: ok`) and now puts the whole payload of a UDP port it does not know in the record as `payload` (hex); **Symbols → Data** takes those records on its `rec` input (*UDP port*) and gives back the file, text or picture. Not in it: confirmed data, header compression, voice, Tier III signalling; a standard radio shows an IP packet, not a picture. Checked without a radio on the generator-free loop of the preset **Data over DMR: Image, File or Text (Loopback)** in headless Chromium: all four modes, all three rates, text in 5 datagrams and a 64×48 JPEG in 6, no bad frames; real hardware has not been tried.
  - **Transmitter, the mirror of the receive chain:** **M17 Frame Builder** (Protocols: from / to callsigns, CAN, message text; frames go out on `go` (rising edge) or the *Send* button — a packet burst of preamble, LSF, SMS packets with CRC and EOT; the `text` input replaces the message, *auto* sends when it changes) → **Symbol Player** (frames → symbols at the baud rate, the carrier stays unmodulated between bursts) → **RRC Pulse Shaper** (symbols → samples at the chosen rate, α, constant symbols keep their level) → **FM Modulator** (IQ at center + offset, deviation per level unit — M17 800 Hz, level −6 dBFS), then HackRF TX (the shaper's output rate must be ≥ 2 MS/s for it). Preset **M17: Transmitter Built from Blocks (Loopback)** feeds the result straight into the receiver chain. Checked in Node: the message comes out of the chain and of the single *Digital Voice Decoder* node, also with noise and at 256 kS/s and 2 MS/s. Voice: **Vocoder Encoder (Codec 2)** (`c2Enc`, Protocols) turns the audio of any node (microphone, file, …) into M17 voice frames — it resamples to 8 kHz and encodes in mode 3200, 16 bytes per 40 ms, as `voice` records of the same shape *Vocoder (mbelib)* reads; the `ptt` input (or always on, when not wired) gates it. **M17 Frame Builder** in *voice (stream)* mode takes them on its `voice` input: while PTT is on (the `ptt` pin or the *PTT on / off* button) it sends the preamble and the LSF, a stream frame per 16 bytes with the LICH and frame number, and at release the last frame (end flag) and EOT. The Codec 2 encoder is the same library as the decoder (`vendor/codec2.wasm`, now with `c2_encode`; byte for byte the same output as a native build of the same sources, checked on 300 frames in both modes). Preset **M17: Voice Transmitter, Microphone to Speaker (Loopback)**: microphone → … → receiver chain → Vocoder → sound card (use headphones)
 On the generator's M17 voice and packet signals the chain plus the parser decode the same calls, packets and Codec 2 frames as the monolith (no FEC errors; a few extra false syncs inside preambles are rejected by the parser's FEC)
- **IQ Add** — sum of two streams of the same rate (for test signals)
- **ADS-B Demodulator** — Mode S frames from a 1090 MHz stream (see [ADS-B](radio.md#ads-b))
- **PSK Demodulator** — soft BPSK/QPSK/OQPSK symbols out as an IQ stream at the symbol rate (see [Meteor-M LRPT](satellites.md#meteor-m-lrpt), [Inmarsat STD-C](radio.md#inmarsat-std-c))

**Workers.** IQ blocks wired to each other form an *island* that runs in its own Web Worker: the main thread only sends it the inputs coming from outside (e.g. the SDR's raw IQ) and the parameters once per engine block, and hands its outputs to the rest of the graph when they come back a block or two later. The IQ → Audio bridge keeps the stream continuous (its buffer covers the delay); numbers and spectra from an island lag by a few milliseconds. Records (`rec`) from an island are queued and delivered once each. Only outputs wired to nodes outside the island come back. IQ → Audio stays on the main thread (it outputs audio), and so do IQ blocks inside groups. The readout of a block in a worker ends with *· worker*. On the generator preset the main-thread load drops from ~40% to ~2%.

Presets: *IQ: Receiver from Blocks (Generator)* and *IQ: Channelizer — Three Signals at Once (Generator)* (no hardware needed), *USB SDR: FM Receiver from Blocks* (stereo, RDS), *USB SDR: HF AM / SSB from Blocks* (DC block, noise blanker, SAM, squelch, auto notch), *USB SDR: Listen to the Strongest Channels* (four strongest NFM channels at once, spread across the stereo field), *Sound Card IQ: HF Receiver (SoftRock-style)* (line-in IQ → balance → SSB/AM), *FUNcube Dongle Pro+: Receiver* (HID tuner control + 192 kHz audio IQ).


### Control logic

Small universal blocks on number wires (a pulse is 0/1, an edge is a crossing of 0.5; unwired inputs are ignored). The *inputs* select (2…8) adds or removes ports; every numeric parameter of every block can also be driven by a wire.

- **Math**: sum, mean, product, min, max, `in1 − rest`, `in1 ÷ rest`, `in1 ^ in2`, `|in1 − in2|`, then gain and offset.
- **Compare**: *above / below / inside / outside* a threshold or window, with hysteresis and a minimum on-time; outputs `out`, `rise`, `fall`. The tile is a small screen: the level history, threshold and hysteresis lines, the on-state shaded. Feed it from Level (dB), Frequency Meter, CFAR SNR, a trend or any number.
- **Logic**: AND, OR, XOR, NAND, NOR, XNOR of 2…8 inputs, `out` and `not`.
- **Select**: `in1…inN` picked by the `sel` index (0 = in1) — e.g. a Flip-Flop output chooses between two frequencies.
- **Flip-Flop**: `set`, `reset`, `clk` (toggle) on rising edges; priority and start state. Two clocks switch something on and off.
- **Sample & Hold**: samples `in` on the `trig` edge, or follows it while `trig` is high.
- **Counter**: counts `clk` edges by *step*, modulo N; `wrap` is a pulse every N-th clock (divider), `phase` is count/N.
- **One-Shot**: a trigger starts a `gate` of *width* after *delay*; `end` pulses when it finishes (a delayed trigger). Retriggerable.
- The **Oscilloscope** has a `hit` output: a pulse each time its trigger fires.

Presets: *Control: Clocks Switch a Tone On and Off*, *Control: Level Trigger (Compare, Counter, One-Shot)*, *Control: Logic Test Bench (all blocks)* (every block in one patch: arpeggio from Counter + Select + Math, gate from Flip-Flop + Compare + Logic, Sample & Hold, One-Shot, scope `hit` counter).

### Indicators

Visual blocks on number wires (Indicators). They draw on a dark screen in both themes and work in the dashboard as tiles.

- **Lamps**: 1…16 round lamps with a glow and labels, one input each. *Threshold* mode lights a lamp at or above the level, *brightness* mode follows the value (0…full scale). *Hold / fade* lets a lamp fade out over the given time, so a one-block pulse (Compare `rise`, a trigger, a flip-flop) is still visible; *blink while on*. Colors are a cycled list: `green, amber, red, blue, teal, violet, pink` or `#rrggbb`.
- **Gauge**: analog needle with a 240° scale, tick labels, optional green / amber / red zones (`amber from`, `red from`), peak marker, needle damping and the value with a unit under the hub. *min* / *max* can be wired.
- **LED Bar**: segmented ladder (horizontal or vertical, by the tile's shape) with the same zones, instant attack, smooth fall and a peak marker. Defaults fit a dB level: −60…0, amber from −18, red from −3.
- **Compass**: azimuth dial with N / E / S / W; `az` is the arrow, `az2` a second marker on the rim (a bearing and a heading, a satellite and the antenna). *Rotate the dial* turns the dial to `az2`. The needle takes the shortest way round 359° → 0°.
- **7-Segment Display**: seven-segment digits (1…12, decimals, leading zeros, unlit segments); *frequency* format turns Hz into kHz / MHz / GHz with the unit. Overflow shows dashes.

- **Sky Plot**: polar plot for azimuth / elevation — north up, the horizon on the rim, zenith in the centre, rings at 30° and 60°. `az` / `el` is the main object, `az2` / `el2` a second one (a satellite and the antenna); a fading trail shows the pass (*trail*, s). An object below the *horizon* is drawn hollow. Wire the `az` / `el` outputs of *Satellites* or a rotator controller to it.
- **S-Meter**: receiver scale S1…S9 (6 dB per step), then +10 … +60 dB; *S9 level* is set in dBm (−73 is the HF standard, use −93 for VHF). Fast attack and slow fall like a real meter, peak marker, the S reading and the level in the corner. The `s` output is the reading in S units (9 = S9, 15 = S9 + 36 dB).
- **Switch**: 1…16 clickable switches, each gives 0 / 1 on `out1…`. Styles: *toggle* (slider), *lever* (tumbler), *rocker*, *button* (latching push button with a glowing ring), *push* (a key that is on only while pressed). The state of latching ones is kept in the patch. Labels and colours as in Lamps; works as a dashboard tile (touch-friendly).
- **Attitude**: artificial horizon — sky / ground, pitch ladder, roll scale with a fixed pointer, aircraft symbol and a slip ball. `roll`, `pitch` in degrees and `slip` −1…1; without roll / pitch, `x` / `y` / `z` of an accelerometer (device flat, screen up) give the angles. *Damping*, *pitch from centre to edge*.
- **ADS-B Radar**: a PPI of the aircraft from the ADS-B Decoder's `rec` around the centre (`lat` / `lon` inputs, the fields, or My Position): range rings, headings, altitude colours, trails, labels (callsign, flight level) and a sweep. Range is *auto* or fixed. Click an aircraft to select it: the line under the dial shows callsign, altitude, speed and distance, and the outputs follow it — `rec`, `az` and `range` from the centre, `alt`, `gs`, `track`, `fpa` (flight path angle from the vertical rate) and `bank` (from the turn rate); `count` is all aircraft. Wire `bank` / `fpa` to an Attitude, `az` to a Compass.
- **Pass**: pass of a satellite — elevation arc between `aos` and `los` (ms, the *Satellites* outputs `aos` / `los` / `maxel` give the next pass), a marker at the current `el`, AOS / LOS countdown, `max` elevation. Without a forecast it draws the elevation history of `el`.
- **Knob**: 1…16 rotary knobs (`out1…`). Drag up / down (Shift — fine), mouse wheel for a step, double click resets to *reset value*. *min* / *max*, *step* (0 — smooth), *linear* or *log* scale (log needs min > 0), unit, labels and colours; the values are kept in the patch. Works as a dashboard tile.
- **Fader**: 1…16 sliders with a scale, the same range / step / scale / reset as Knob; a click sets the value, drag moves it, the wheel nudges.
- **XY Pad**: a touch pad with `x`, `y` (each with its own min / max) and `touch` (1 while pressed). *Spring back* returns to the centre on release, *grid lines* and *snap to grid*; the position is kept in the patch.
- **Tank**: level of a number as a filled tube (vertical or horizontal by the tile's shape) with a scale, damping, dashed *low* / *high* alarm lines and min / max markers (a click resets them; for a history use *Trend Chart*, window up to 24 h). The fill turns amber below *low* and red above *high*; `low` / `high` outputs give 0 / 1 for the alarms.
- **Tuning Dial** (`dial`): a receiver scale — swipe or drag it sideways and it slides under the needle (after a flick it keeps gliding), the wheel steps one *tuning step* (Shift — ten); *fixed* mode runs the needle along the whole band instead. Units Hz…GHz (`f` out is always Hz), band start / end, snap to the step, backlight colour; a number on `in` sets the frequency (e.g. from a Rig Control / SDR `f`). The position is kept in the patch.
- **Magic Eye** (`eye`): the tube tuning indicator — round 6E5 (a dark wedge closes as the level rises) or the EM84 bar (two bars meet), phosphor colour and damping, `invert`. Feed it a level in dB (Level / Stats `db`, set *min* / *max*) or an S-meter reading. Preset *Indicators: Radio Tuning Dial and Magic Eye (stream)*.
- **S-Meter (needle)** (`smeterneedle`): a receiver needle meter, S1…S9 then +20 / +40 / +60 in red; *S9 level* in dBm (−73 HF, −93 VHF), attack / fall, peak marker, dial colour and backlight; `s` out in S units. **SWR / Power Meter** (`swrmeter`): crossing needles — forward (`fwd`) and reflected (`ref`) power, SWR is computed (`swr` out, red above *warn*). **Tuning Meter** (`tunemeter`): centre-zero needle for an offset (AFC / discriminator) with an «in tune» band; `tuned` out. Preset *Indicators: Analog Radio Meters (S-Meter, SWR, Tuning)*.
- **Entering and showing numbers** (`modules/entry.js`, logic in `entry-kernels.js`, `node tools/test-entry.mjs`): **Number Pad** (digits 0–9, `.`, ±, ⌫, C, ENT; in *frequency* mode the unit keys GHz / MHz / kHz / Hz commit the value, ENT uses the unit set in the node, in *number* mode the suffix keys are M / k / m / µ; `set` in, `out` / `live` / `enter` out, optional clamp), **Pocket Calculator** (expression with `+ − × ÷ ^ %`, brackets, `ANS`, memory, with *scientific* keys: sin cos tan ln log √ x² π e, deg / rad, `A` / `B` from the pins; no `eval` — own parser; `out` is the result, or the running one with *live*; the existing **Calculator** in Tools is the formula one), **Frequency Digits** (VFO digits: tap the arrows above / below a digit, swipe it vertically or use the wheel to step that decade; a tap on the digit itself selects it — then ↑ / ↓ step it, ← / → move to a neighbour digit, typing 0–9 sets the digit and moves right, Esc releases, `in` sets, `f` out in Hz), **Number Readout** (frequency / SI / plain / groups of three, styles LCD, VFD, LED, paper). The computer keyboard works too (click the node, type). Preset *Indicators: Number Pad, Frequency Digits, Calculator and Readouts*.
- **Taps and gestures in the floating window** (phone app): a node whose canvas takes touch itself (`indWire` controls — Number Pad, Calculator, Frequency Digits, Tuning Dial, Knob, Fader, XY Pad, Switch, Key Panel…; canvases with their own pinch — Spectrum Analyzer, map, audio editor; anything marked `touch` in its module) opens its 🗔 window in *touch* mode: every finger goes to the node (`DspApp` → `FloatWin.onTouch(id, act, x, y, finger)` → `floatTouch` in `floatwin.js` → pointer events on the node's canvas), so drag, tap, pinch-zoom of a spectrum or a map work as on the page; for canvases that zoom with the mouse wheel only, two fingers become wheel events. The window is moved by the ✥ corner (× closes, ◢ resizes as before). The system keyboard cannot be used over other apps (such a window must not take focus), hence the on-screen keypads. Pocket Calculator has a *simple* layout (big keys, default, made for a floating window) and a *scientific* one; a tap on its display switches between them.
- **Android build**: the page files go into the APK as they are, so the *Android app* workflow also runs on changes to the web part (`index.html`, `modules/`, `presets.js`, …), not only to `tools/android`; each merge into `main` publishes a release whose number (1.N, N = run number, also the `versionCode`) goes up with it.
- **Audio Stream in the phone app**: a station whose server sends no CORS headers (or which the WebView's media stack refuses to open through the app's own proxy) is fetched with `fetch` and played through MediaSource (mp3 / ADTS-AAC), so it still reaches the graph; the node status names the real reason if both ways fail.
- **Text Panel** (Indicators): the simplest universal HUD — lines of text with values from the pins `a…h` (numbers) and `s1…s4` (text), drawn on a canvas, so it works in the dashboard, PiP, as the live wallpaper and in a window over other apps. Language: `{a:0.0}` value (`0`, `0.00`, `+0.0`, `%`, `si`, `hms`, `bytes`, `hex`, `onoff`, `{now:HH:mm:ss}`), `[red if a>100]text[/]` colour of a part by a condition (comparisons, `&&`, `||`, `!`, arithmetic, strings), `# ` / `## ` / `-# ` headings, `**bold**`, a rule for the whole line `… | red if a>100; amber if a>60; green`, `@bar a 0..100 label | rules` bars, `@graph a,b 60 0..100 | red, cyan` charts of the last N seconds (`auto` — by the data), `@sep`. Background (any CSS colour with alpha) and text size are parameters; the text shrinks to the tile.
- **Mock GPS** (Sources, DSP app, developer): fake location — every app on the phone and our own GPS source see the point. Route (lines `lat,lon[,alt]`, GPX or KML, loop / ping-pong / stop) at a speed in m/s, a circle, one point, or the `lat` / `lon` pins; accuracy, scatter, update rate, providers gps / network / passive; outputs `cmd` (→ Phone Control), position, bearing, progress, distance. Needs the app chosen once in Settings → Developer options → *Select mock location app*; the phone's answer (`permission`) is shown in the node.
- **Float over other apps** (DSP app): the 🗔 button in a node header (and in the dashboard) floats the picture of that node's canvas over every other app — a Text Panel, Gauge, Tank, spectrum, map; several windows at once, drag to move, ◢ resizes, × closes, position is remembered. Frames come from the engine tick, so it keeps updating while the page is hidden. Needs *Display over other apps* (the system screen opens on the first press).
- **Packets** (Data): **Packet Crafter** builds a packet layer by layer — Ethernet / ARP / IPv4 / IPv6 / TCP / UDP / ICMP / ICMPv6 + a payload (text with `\r \n \xNN`, hex, N zero bytes or `abc…`); lengths and checksums with the pseudo-header are computed, both checksums can be broken on purpose; templates ARP who-has / is-at, ping, ICMPv6, TCP SYN / RST / FIN / Xmas, UDP, DNS, mDNS, SSDP, DHCP discover, Wake-on-LAN, NTP. *Send*: a count, a rate and a field that grows by 1 in every packet (port sweep, TTL ladder). Outputs `bin`, `hex`, `rec` (for Packet Analyzer / PCAP Writer) and `cmd`: `raw.send` (a whole IPv4 packet, **root** in the DSP app) or `udp.send` (a socket, no root) for Network (DSP app); ARP, Ethernet frames and IPv6 stay in the outputs — Android has no frame injection. Send only to hosts you are allowed to test. **Packet Analyzer** takes records with `hex` (Network Monitor VPN packets, root tcpdump, Wi-Fi Sniffer, PCAP Reader, Packet Crafter) or a file (pcap, pcapng, a text hex dump) and gives a tshark-style line per packet (ARP, IPv4 / IPv6, TCP flags, UDP, ICMP, DNS / mDNS, HTTP / SSDP, TLS hello), a **display filter** (`tcp.port == 443 && ip.addr == 10.0.0.0/8`, `!arp`, `dns`, `tcp.flags.syn`, `info contains "GET"`), statistics, the last packet as fields or hexdump, and **export** to pcap, pcapng, text2pcap hexdump, xxd, JSON, CSV, C array, Python bytes (import also reads `hexdump -C`, `\x..`, `0x..`, base64). Dissectors are the HEX Structure schemas, so every protocol added there can be shown in the Hex node.
- **Panels** (faceplates; the buttons are separate nodes so one panel drives any display):
  - **Radio Display (base station)**: big 7-segment frequency, mode badges (LSB USB CW AM FM DIG), VFO / name, S-meter S1…S9+60, BUSY / TX lamps. Pins: `freq` (Hz), `s` (dBm), `mode`, `tx`, `sql`, `name`, `vfo`.
  - **Radio Display (mobile)**: an LCD with signal bars, TX / RX / BUSY, battery, channel, name, mode and volume; backlight of any colour (`hue` 0–360 or `#rrggbb`), *negative* (glowing digits) or *positive* (dark digits on a lit panel).
  - **Spectrum Analyzer Display**: a lab CRT with a graticule or a colour handheld LCD for an `spec` wire; averaging, peak hold, a marker on the peak, outputs `peak` / `pf`; `f0` / `f1` set the frequency axis, `ref` / `floor` the dB scale (wire a Knob there).
  - **Detector**: *metal* (needle, target ID, FE scale — the magnetometer `x` `y` `z` is compared with a slowly following baseline, i.e. automatic ground balance; a click sets it by hand), *bug* (LED ladder), *emf* (five lamps), *geiger* (CPM → µSv/h). Outputs `level`, `delta`, `id`, `alarm`, `tone` (Hz for an oscillator). The target ID is a heuristic by the sign of the field change.
  - **Needle Meter**: a backlit VU-style panel (1 or 2 channels, any dial colour, ballistics, red zone, peak lamp).
  - **Speedometer**: dial plus a mechanical odometer and a trip drum that persist in the patch; wire unit (m/s for GPS) and dial unit (km/h, mph, m/s, kn) are separate; `reset` or a click on the drum zeroes the trip.

  - **Key Panel**: hardware-style keys (layouts radio, scanner, numeric, transport, tuning or your own list; push or latch; rubber / mechanical / flat / round); outputs `k1…kN`, `last`, `key`, `hit`.
  - **D-pad**: four sides, OK and four corner buttons (`a`…`d`, labels are yours) inside a square; outputs `up down left right ok a b c d`, axes `x` `y`, `key`.
  - **Rotary Selector**: a wafer switch with 2…12 positions (click / drag the knob, the wheel steps), outputs `pos`, `val` (your value list) and `label`. **Jog Wheel**: an endless encoder with a push button — `delta` per block, accumulated `pos` (step per detent), `dir`, `push`, `rec`.
  - **DIP Switch**: 4…16 sliders, outputs `b1…bN`, `value` and `bits`. **Flip Clock**: split-flap cards for the time (local / UTC, 12 / 24 h, seconds) or for any number.
  - **Character Display**: 5×7 dot-matrix text — LCD (dark dots on a lit panel), negative LCD, VFD or OLED, 8…40 columns, 1…4 lines from `l1…l4` / `text`, backlight of any colour.
  - **Goniometer**: a vectorscope of two `sig` wires (M/S axes at 45° or plain XY) with a correlation meter (`corr`, `bal`). **Thermometer**: a glass column (horizontal on a wide tile) or a dial, °C / °F / K, min / max markers (a click resets).
  - **Phone volume keys**: Key Panel's layout *phone* puts a ready command on `cmd` (VOL− / VOL+ / MUTE → `vol.adjust`, PREV / PLAY / NEXT → `media`) for Phone Control; Key Panel and D-pad also emit `rec` records, and Rule has templates «volume up / down», «mute on / off».
  - Unlit segments of the 7-Segment Display and of these panels are almost invisible.
- **Text Ticker**: the latest lines from `text` (a new string is a new line) and `rec` (the *field* is shown, or all fields as `key=value`), as a scrolling log with optional timestamps or as a running line (*marquee*). *Clear* empties it. Good for a decoder's messages next to the other indicators.

- **Graph** (Output): a link graph (vis-network, bundled). There is no data window, everything comes over wires. **`rows`** takes the whole set at once — wire a [Table](data.md#table)'s `rows` to it: a record with `from,to[,weight[,label[,color]]]` (also `source`/`target`, `src`/`dst`) is an edge. The other records of `rows` are the nodes: `id` (or `node`, `name`), `label`, `shape` (`dot`, `circle`, `square`, `box`, `diamond`, `triangle`, `star`, `hexagon`, `ellipse`, `database`, `text`), `color`, `size`; a node without a record gets the defaults (size by degree), a node record without edges is drawn alone. Fields are found by name in this order: `from` / `source` / `src`, `to` / `target` / `dst`, `weight` / `value` / `count`, `label` / `name` (a record that has only one end is skipped, so aliases and voice frames do not make edges; `src` is not taken for a source when the record has `kind` or `msg` — there it is the protocol name); an `alias` field of a record (or a record with only `from` and `alias`) labels the sender node as `alias` over its id; *advanced → prefix for to* (`call=group:TG `) puts a prefix on the addressee id when a field has a value, so talkgroup 9 and radio 9 are two nodes; *advanced → … col* names the columns explicitly. Protocol logs work the same way: wire a decoder's `rec` (DMR, M17, P25… and FT8 give `from` / `to`) into a Table, filter it (DMR: `kind:call|alias`, FT8: `to:` — CQ calls have no addressee) and wire `rows` to `rows` — every repeated call thickens the edge. A set replaces the previous one: what is gone from the table disappears from the graph, edits are applied, and only the difference is sent to the view (the layout stays, nothing is redrawn without a reason); unwiring a port empties its layer. `rec` (one record = one edge) and `text` (a chunk of CSV on every change) only add edges as they come, for streams. A repeated pair without a weight thickens the edge. *arrows*, *weights on edges*, *physics*; *Clear* wipes what `rec` / `text` collected; clicking a node puts its name on `sel`; `nodes` / `edges` are counters. Preset *Graph: Links from CSV*. (The old *csv* field of saved patches is still read.)
- **Graph: groups, pictures, arrows, layouts and comments** (`modules/graphview.js`, logic in `modules/graphview-kernels.js`, `node tools/test-graphview.mjs`; preset «Graph: Groups, Pictures, Arrows, Tree and Comments»). Node rows (from a Table's `rows`; **Rec → Entities** records need a Table in between, the `rec` input only adds links): `group` (nodes of a group share a colour taken from the name, unless `color` is set; *Cluster groups* / *Open clusters* fold and unfold them; the column can be changed in advanced settings, e.g. `type`), `image` (a picture — a `data:` URL or a file of the app, the node becomes round; `shape=image` keeps it square), `glyph` (a symbol or an emoji drawn as the node; `icon=📶` works too, the map icon names such as `antenna` still pick a shape), `shape` (adds `image`, `circularImage`, `icon` to the old list). Link rows: `arrows` — `to`, `from`, `both`, `middle`, `none`, or per end `to:circle,from:bar` (types arrow, bar, circle, box, diamond, curve, inv_curve, triangle, vee; `->`, `<-`, `<->` work too); empty — the node's «arrows» tick decides. Settings: **layout** `free` / tree `UD` `DU` `LR` `RL` (tree order `directed` by link direction or `hubsize`, level and node gaps in advanced), **physics solver** (forceAtlas2Based, barnesHut, repulsion, hierarchicalRepulsion; a tree always uses hierarchicalRepulsion), **edge curve** (dynamic, continuous, curvedCW / CCW, cubicBezier). **Editing**: click a node and a panel edits its label, comment (`note`, shown under the label), group, colour, shape, image, symbol, size; *Save* shows it at once (kept in the patch, *Reset* returns to the table's values) and sends `{id, …changes}` to the `edit` output — wire it to the Table's `rec` (upsert by `id`, as the map does).
- **Table Chart** (Output): a chart from the rows of a Table (wire `rows` or `all`, like Graph). *x* / *y* columns are found by name (`chan`, `t`, `rssi_max`, `busy`, `csi`…) or set by hand; several *y* columns or a *series by* column give several series. Bars (up to 64 different x, e.g. channels) or lines (time, many rows); *peak hold* keeps the highest value per x; a fixed range or auto. A cell like `3,5,4,…` (or an array) is a vector: it is drawn as a line over the index, the last *N* rows overlaid (older fainter) or as a waterfall (*heat*) — CSI, spectra. Outputs `max`, `count`. Aggregate first with *Rec → Entities* + a keyed Table (one row per channel / device) if needed.
- **Rec → Entities** (Data): turns one decoder record into entities and links by rules, one per line: `[out:] conditions | fields`. Conditions (space-separated, all must match): `field` (has a value), `!field`, `field=a|b`, `field!=a`, `field~regex`. Fields (comma-separated): `name=template` (`{f}` a record field, `{f:x}` number as hex, `{a|b}` the first non-empty one, `{f*}` an array field — one record per element), a bare `name` (copied if present), `*` (all fields); a template with an empty field skips the rule for that record. `out` names an output port (a table per entity type: cell, operator, subscriber, talkgroup, link…); `rec` carries everything. *insert rules* adds ready sets: **GSM cells** (cell → operator, cell → ARFCN) and **Digital voice** (subscribers, talkgroups, membership and private calls; the `{src}` prefix keeps DMR / P25 / NXDN ids apart). Wire `rec` into a **Table** with *upsert key col* = `id`, then its `rows` into **Graph**: nodes with `shape` / `color` / `label`, edges `from` → `to`. Presets *Entities: …* — made-up data and real USB SDR chains (DMR, GSM). The «Phone radios (Wi-Fi · BLE · Bluetooth)» rules split the records of the DSP app into three outputs (`gw`, `gb`, `gt`) — one graph each; the preset «Phone App: Wi-Fi, BLE and Bluetooth as Three Graphs» wires them to Tables and Graphs with the vendor under each node (OUI, WPS, BLE company, service). BLE records of the Phone node carry `mfrId` (company ids as an array) for such rules.
- **Entity Card** (Output): the card of one entity from a Table's `rows` (the same set as for Graph). `sel` takes the selected id — wire **Graph**'s `sel` to it: a click on a node shows the title and type, `count` / `first` / `last`, the other columns as attributes and the links in both directions grouped by label (→ outgoing, ← incoming). A click on a linked entity opens it (← goes back), the search box finds an entity by id or name. Outputs: `sel`, `rec` (the row of the open entity) and `links` (their number). Preset *Entities: …*.
- **Chat** (Output): incoming text from the `text` wire goes into the log, the field at the bottom sends (Enter or *Send*): `text` holds the last sent message, `go` pulses for one block. A text on the `send` input is sent the same way. Preset *Chat: Text In and Out*. **Group chat**: the `rows` pin takes the participants (a Table: `name`, `avatar`, `online`, `typing`) — a strip of avatars with the online dot above the log and «… is typing» under it; `from` names the author of incoming `text`, `rec` takes ready messages (`from`, `text`); with one other participant in `rows` the dialog needs no `from`. *my name* marks your own messages (shown on the right). Preset «Chat: Group with Avatars and Contact List».
- **Two-player games** (Output): *Tic-Tac-Toe*, *Connect Four*, *Battleship*, *Reversi* (legal moves are marked, a player with no move is skipped, the game ends when nobody can move). Ports like Chat: `in` — the opponent's moves, `out` — yours (text), `go` pulses per move; plus `turn` (1 on your move), `result` (1 win / −1 loss) and a `new` input (rising edge = new game). Any text channel works: *WebRTC Data* (`line` → `in`, `out` → `send`), *MQTT* (one shared topic — a node ignores its own messages), *Text over Network*. A hello handshake picks the first player (or set `side`), every next game starts with the other one; the *New game* button restarts both sides. Messages are `<game>:<nonce>:<seq>:<command>`, e.g. `gtictactoe:k3j9x0aa:5:m 4`. Presets *Game: … over WebRTC*, *Game: Tic-Tac-Toe over MQTT*, *Game: Reversi over Sound (TBSK)*. **Lossy channel** (`rel`, off by default): for a link that drops or corrupts messages (sound, radio) every message gets a checksum, moves are numbered, the other side confirms them (`ack`) and an unconfirmed move is sent again after *resend* seconds (random +0…50%), a duplicate is not applied twice, a corrupted or out-of-order one is dropped. Both sides need the same setting. `go` is a rising edge for every message (one block of pause between them), so it can be wired to the *TBSK Modulator*'s `go` (with `out` → `text`); the modulator queues frames that arrive during a transmission instead of cutting the current one. Over TBSK the channel is half-duplex (a move is ~30 bytes: ≈1 s at 300 bit/s), a collision of two bursts is covered by the resend. Checked in `node tools/test-games.mjs`: two Reversi nodes through the real TBSK modulator and decoder, with noise and with every fifth burst cut by a 0.25 s dropout, both sides finish with equal boards; not tried with real speakers and microphones yet.

Code fields (Script, Builder, Note, tables) are a plain text area with a light syntax highlight underneath, so the caret stays in place at any canvas zoom; the Note has no highlight.

Presets: *Indicators: Lamps, Gauge, LED Bar, Compass, Display*, *Indicators: Sky Plot, S-Meter, Text Ticker*, *Indicators: Switches and Attitude*, *ADS-B: Radar and Attitude (Generator)*, *Satellites: Pass and Sky Plot*.

### Dashboard tiles

The ▦ button switches to a tiled dashboard built from the modules of the current patch:

- Pick any module for each pane from its dropdown
- **Tabs in a pane**: **+** next to the dropdown adds a tab, so one pane switches between several modules; the dropdown belongs to the active tab, ⨯ closes it
- Split panes right (⬌) or down (⬍), remove them (✕), drag dividers to resize; panes sit edge to edge, 1px dividers
- **⊡** or a double-click (double-tap) on an empty spot of the pane header maximizes the pane; the same restores the layout
- In narrow panes and on touch the pane buttons fold into **⋯**
- Module displays follow the light theme too (light screen, dark ink); the spectrum analyzer waterfall, persistence, the Map and Video Overlay stay dark
- ⛶ shows only the module's display, without controls, header, frames or selection; the button stays in the pane header on touch too
- **✎** (pane menu, or in a module's header on the canvas) gives a module its own name — it shows in the header, the pane dropdown and the tab (empty name — the default one)
- With no module graph pane on the page, the editing buttons of the toolbar (undo / redo, duplicate, chain, clear, fit, detail) are hidden
- **▶** also asks for the camera and motion sensors at once for modules that need them (Camera, Orientation, Accelerometer, Sensor), so a Video Overlay shows the picture right away
- **Tile pages**: **+** next to ▦ adds another set of tiles; switch pages with the numbered buttons, tap the active one to rename, duplicate, reorder or delete it. A module can appear on several pages
- The layout is saved with the patch and works on touch devices (wide scroll rail for long panes)

### On a phone

- **Screen stays on** while the graph runs (Settings → *Keep screen on*, on by default; needs the Screen Wake Lock API).
- **Background audio**: while running, a silent media element is attached to the audio engine, so the browser treats the page as playing media (it is not put to sleep with the screen off) and the lock screen shows play / pause. Without a sound output Chrome may still throttle the page. If the browser suspends the audio context (screen lock, a call, iOS *interrupted*), it is resumed on return; on iOS/Safari the audio session is set to *playback*.
- **Back gesture** closes what is open — the sidebar sheet, a maximized tile, ⛶ canvas-only mode, the settings panel, the module search — instead of leaving the app.

### Processing

- Filters, gain, mixers (4/12 ch), AGC, squelch, mains notch, adaptive hum canceller (tracks mains frequency, all harmonics), comb notch, adaptive filter, spectral denoiser
- **Echo Canceller (AEC)** (Audio, `modules/aec.js`, logic in `modules/aec-kernels.js`, `node tools/test-aec.mjs`): removes from the microphone what the speaker played. Inputs `mic` and `ref` (what plays on the speaker / the far end, or a second microphone near a noise source): a partitioned-block frequency-domain adaptive filter (PBFDAF, overlap-save) learns the path ref → mic (delay and room tail up to 512 ms), converges in ~3 s (≈24 dB at 3 s, 50+ dB later on a synthetic path), keeps the near voice during double talk (adaptation slows when the error is loud; the first 2 s of an active reference adapt without that gate) and a soft suppressor removes the residual. Outputs `out`, `echo` (what was removed), `erle` (dB), `delay` (the path found, ms). **One microphone** (`ref` not wired): the filter predicts the signal from its own past later than *remove repeats later than* (20…400 ms) and subtracts it — echoes, a repeater that doubles the signal, long reverb; the voice itself stays (a sustained tone or a strongly periodic sound is predictable too and gets reduced, so keep the delay above the pitch period). Delay of the node: 256 samples (5.3 ms at 48 kHz); cost 3.5 % of a core for 128 ms, 7 % for 512 ms at 48 kHz (measured in Node).
- **Voice Restore (de-mumble)** (Audio, `modules/voicerestore.js`, logic in `modules/voicerestore-kernels.js`, `node tools/test-voicerestore.mjs`): for speech that went through a narrow filter and sounds muffled / mumbling / boomy. It learns from the speech itself (about 1 s of active speech): the long-term spectrum in ⅓-octave bands is compared with a typical speech spectrum (LTASS shape) and the bands are corrected (boost up to *max boost*, cut up to 12 dB; bands near the noise floor are not lifted), then the top that is missing above the found cut-off is rebuilt by shifting the lower octave up and shaping it like speech (the rebuilt top is plausible, not the original; on a synthetic test the spectral error of a 1.2 kHz wall dropped 20.6 → 12.3 dB with the equalizer and → 6.6 dB with the extension; speech that already has a typical spectrum changes by < 0.2 dB). Parameters: equalizer strength, extension, rumble cut (24 dB/oct below *boom*), max boost, learning time, bypass; output `cut` (the cut-off found, Hz). STFT with 75 % overlap, delay N samples (21 ms at 48 kHz). A mains hum or a drone: put the *Hum Filter* before it. Not a neural network: a blind equalizer plus bandwidth extension.
- **Neural audio** (`modules/nnaudio.js`, streaming wrapper in `modules/nnaudio-kernels.js`, `node tools/test-nnaudio.mjs`; models run in the browser, no network needed): **Denoiser (RNNoise)** (Audio) — a small recurrent network (112 KB WASM, `vendor/rnnoise.wasm`, Xiph RNNoise 0.1 built by Jitsi) that suppresses noise in speech; `in` → `out`, `mix` (0…1), outputs `vad` (speech probability) and `speech` (1 above the threshold). 10 ms delay; the net works on 48 kHz frames, other engine rates are resampled (linear). It needs a few seconds to learn stationary noise. Big models of this family are kept in Files → Offline data and listed under *⇩ offline*.
- **Sound Classifier (YAMNet)** (Analysis, `modules/yamnet.js`, logic in `modules/yamnet-kernels.js`, `node tools/test-yamnet.mjs`): Google YAMNet through MediaPipe Tasks Audio (WASM, in the browser) names the sound in a ~1 s window out of 521 AudioSet classes (speech, music, siren, engine, dog, white noise…). Input `in`; outputs `text` (top classes with shares), `label`, `score`, `hit` (1 while a class from *watch for* is heard — substring match, e.g. `speech` also catches «Male speech»), `rec` (an event when a watched class appears). Parameters: classify every, classes to show, min share, watch list, watch threshold. The window is averaged down to 16 kHz exactly (15 600 samples). ~11 MB (`vendor/mediapipe/`: MediaPipe 1.1.1 wasm + `yamnet.tflite`) are fetched once into Files → Offline data and listed under *⇩ offline*; SIMD build only.
- **Speech to Text (Whisper)** (Analysis, `modules/whisper.js`, logic in `modules/whisper-kernels.js`, worker `whisper-worker.js`, runtime in `vendor/whisper/`, `node tools/test-whisper.mjs`): OpenAI Whisper (ONNX, q8) through Transformers.js + ONNX Runtime Web (WASM, in a separate thread — the graph does not stall). Input `in`; the stream is cut into phrases by pauses (threshold in dBFS plus a self-adjusting noise floor, pause, longest phrase 5…28 s), each phrase is recognised: outputs `text` (last phrase), `full` (transcript), `go` (pulse per phrase), `rec` (event with text and time), `count`, `busy` (phrases waiting). ~100 languages (Russian included), *language* auto or fixed (fixed is more reliable on radio), *translate* to English; models tiny (≈45 MB) / base (≈85) / small (≈270) / large-v3-turbo (≈800 MB, the most accurate, needs a fast PC) and the `.en` variants; *norep* fights word loops (the decoder bans repeated 5-grams, long runs of one word are collapsed); or any ONNX Whisper repo from huggingface.co in *own model repo*. Typical Whisper inventions on silence («Thank you.», `[BLANK_AUDIO]`, loops) are dropped (*junk* option); optional `[m:ss]` stamps; buttons *Transcribe file…* (audio/video, faster than real time), *Clear*, *Save text*. The runtime (≈15 MB, `vendor/whisper/`) and the model files are fetched once into Files → Offline data (⇩ offline: runtime + tiny) and then work without a network; the worker never goes to the network itself — the page serves it the files. If huggingface.co is not reachable from the network, in Files → Offline data every item with http sources has a *by hand* section: open each link in a new tab (the browser saves the file), then *choose downloaded files…* and pick them — the names are matched (for Whisper `.onnx` go to `onnx/`) and the files land in Files → Offline data (`OfflineData.save`). The model shows up in the ticker via `rec`. See the preset «Speech to Text (Whisper)».
- **Notes (Basic Pitch)** (Analysis, `modules/pitchnn.js`, logic in `modules/pitchnn-kernels.js`, `node tools/test-pitchnn.mjs`): Spotify's Basic Pitch (TF.js, ~0.9 MB model in `vendor/basicpitch/`) hears several notes at once. Every *analyse every* s it takes the last ≈2 s, resamples to 22 050 Hz and reads the note probabilities of the last frames; outputs `text` (`C4 E4 G4`), `n`, `midi` and `hz` of the strongest, `rec` (an event when a note appears). The answer lags about a second; heavy on the CPU (≈2 s per window on the `cpu` backend, much less on WebGL). TF.js is shared with Object Detect; everything is fetched once into Files → Offline data (*⇩ offline*).
