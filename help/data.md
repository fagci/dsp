# Tables and records

Many modules (decoders, scanners, phone sensors) emit **records** — small objects like `{proto:'ble', src:'aa:bb', rssi:-60}` — on a `rec` pin. Other modules turn them into something you can see.

## Viewers
- **Graph** — rows with `from` and `to` become links; rows with an `id` become nodes. Node columns: `label`, `group`, `color`, `shape`, `image`, `glyph`, `note`, `size`. Link columns: `weight`, `label`, `color`, `dashes`, `arrows`. Click a node to edit it; changes can go back to the Table through the `edit` output. The full module description is in [Processing and interface](processing.md#indicators).
- **Map** — rows with `lat` and `lon` become points; link rows become lines. Details: [Map and records](map.md#map-and-records).
- **Entity Card** — details of the node selected in a Graph.
- Rec Log, charts and other viewers take `rec` directly.

## Table

One node for everything that is a list of records: the former Data Sequencer, Band Plan, Bookmarks, List (CSV/DB) and CSV Log. (They are still in the palette under *show legacy*, so old patches keep working; new work should use **Table**.)

- **Layout**: one list picker with search (nested folders that collapse and expand, only the name is shown; a search opens everything it finds): a click on a name makes the list active and closes the panel, a tick next to it (or next to a folder) shows the list on the `rows` output (Map, band plan on the spectrum) and keeps the panel open (*none* clears; the button shows ☑N when several lists are on), **＋** right after it (new list: empty or from a template) and **⋯** with every action in groups — Rows, Data (import / open data / export), List (copy, rename, move to folder, template columns, delete), View (columns, first / last rows). The tile has two rows of controls: the list picker with ＋ (new list) and ⋯, and the filter with `+ row`, the view switch (cards / full list / brief list / icons) and the ▦ schema button (fields, roles, columns, colours, list settings — the one panel; the rows wrap on a narrow tile); a point at your position is the **Mark Point** node (preset *Map Points: Mark My Position → Table → Map*), not a Table button. Editing a row opens a panel at the bottom of the tile (two columns, *save* / *cancel* at the top) over a fixed-height list — it does not scroll with the rows and the list never changes height; double-click a row to edit it. The former sections below describe the same functions.
- **Lists and folders** (Sources → *Table*): a list is a table of records. It lives in the browser database (like the sample library, `folder/name` makes a folder; ＋ ✎ 🗑 create, rename / move, delete the active list). The lists are shown in **one picker, nested collapsible folders, each list and folder with a checkbox**: a click on a name makes the list *active* (its rows are listed and edited) and does not touch the checkboxes, only a checkbox shows the list on `rows` — tick any number of lists or a whole folder and `rows` becomes their union, one *filter* applies to all of them (`kind=video`, `note:ELRS`). The ticked lists and the open folders are remembered in the patch, or in the patch itself (list `@patch`: the data travels with the patch file), or it is one of the built-in band plans (folder `presets`, read-only, ~55 plans in folders — *Drones* (FPV video 5.8 / 1.2 / 2.4 / 3.3 GHz channels, RC and telemetry links, DJI / Autel / Parrot models, military link classes, counter-UAS bands, Remote ID), *Wireless* (Wi-Fi 2.4 / 5 / 6E / 60 GHz channels, Bluetooth and BLE channels, Zigbee / Thread, nRF24 ch0–125), *LoRa* (LoRaWAN EU868 / US915 / AU915 / Asia channels, Meshtastic, Sigfox, Z-Wave, wM-Bus), *SubGHz* (315 / 433 / 868 / 915 MHz), *Audio* (wireless microphones, DECT, baby monitors), *Navigation* (GNSS incl. GLONASS FDMA, aero), *Satellite* (Inmarsat, Iridium, weather, amateur / CubeSat, UHF 225–400, TV Ku/C, Starlink), *Cellular*, *Voice* (CB, PMR446, LPD433, FRS, MURS), *Stable* (time stations, VLF navy, beacons, 24/7 channels) and *Bands* (ITU names from ELF, IEEE / NATO letter bands L S C X Ku K Ka, infrasound and geophysical signals). Columns `kind` (`video`, `control`, `telemetry`, `channel`…) and `note` explain the rows; frequencies are a guide, not an official document; **copy** turns one into your own list, or moves a list into the patch and back). Old Bookmarks / Band Plan / List lists open as they are.
- **Your own database (cards, fields, links)**: **▦ schema → Fields** gives each column a type — *text, long text, number, checkbox, date, choice (your options), photo, audio, link to a list* — and a tick *show on the card*; the type is kept with the list (a list in the patch keeps it in the patch; copy, export of all lists and backup carry it). The entry form follows the types (number / date pickers, checkbox, choice menu, a photo strip with camera / gallery in any column typed *photo*, a picker for links with search and **＋ create** for a new entry in the linked list). Three views, switched by the button next to **▦ schema**: **cards** (cover photo, name, chosen fields, links as chips; a tap opens the entry card), **full list** (columns) and **brief list** (name · values). The *entry card* shows the big photo with thumbnails, all fields, the links (a tap on a chip opens that entry, even in another list) and *linked from* — the entries of other lists that point here; ◀ ▶ step through the entries. A link stores the names of the entries (`A | B`), so it survives export and import; renaming an entry or a list updates the links that point to it. Template *Collection (cards with a photo)* gives a ready start. Logic: `modules/table-cards.js`
- **Checklist** (field type *checklist*): a task list for every record — shopping in several shops, things to do at each point of a trip. The field is not stored: it shows `☑ 3/7` (done / all), counted from another list whose rows have a *link* to the record and a *checkbox*. Pick the type in **▦ schema → Fields** and the sub-list (`<list> <field>`: `name`, a link to this list, `done`) is created for you, or point the field at any list with a link and a checkbox column. A tap on `☑ 3/7` in the list (or the card of the record) shows the items with checkboxes and a field to add one; **open list ▸** drops into the sub-list filtered by the record, with **← record** above it to come back to the card, new rows there get the link filled in, and a tap on the ✓ cell ticks an item. For other nodes the row carries `<field>` (`3/7`), `<field>_done`, `<field>_total` and `check_done` / `check_total` (sums over the checklist fields) — filter by `check_done < check_total`. The Map shows `3/7` on the point (green when all done); a tap on such a point opens its items right on the map (tick, add), and the numbers follow through the Table. Only the active and the ticked lists are counted; deleting a record leaves its items in the sub-list.
- **Card layout, files, back** (▦ schema → *Card layout*): *customize* puts the fields on lines under the card title — a field list per line, ▲ ▼ move a line, a click on a field removes it; *captions* adds field names before the values, *photo block* off gives text-only cards (a card without a photo keeps its letter tile and no longer collapses in a long list). Field type **file (from Files)** stores file ids (`fl-12`; photos of the *images* space as `ph-…`) in the cell: **📁 pick** in the form opens the file manager (double click or *＋ selected*), the cell shows the file name — click opens an image / plays audio / downloads the rest. After a jump along a link (a chip on a card) the card has **←** to return to the previous entry and list; ✕ clears the trail.
- **Table, list with icons** (👤 view button): a row = avatar, name, values. Column types *avatar / image* (an `https://` link, a `data:` image, a photo from Photos, an emoji; otherwise a letter on a colour), *online status* (online / away / busy / offline, or 1 / 0 — a dot on the avatar) and *typing* (animated dots instead of the values); columns named `avatar`, `online`, `typing` work without a schema. Good for a contact list and a list of received SSTV pictures.
- **Column templates**: **＋** opens a menu — an empty list, or a list created at once with the columns of a template — and **⊞** adds the columns of a template that are missing to the active list (the data and the other columns stay; a name that already exists is only completed, never overwritten). Templates: *Map points* (`name lat lon alt h icon color note`), *Field measurements (point + height)* (what Mark Point writes: `name t session tx lat lon alt h freq rssi azimuth elevation rx_ant rx_gain note photo`), *Frequencies* (`name freq demod bw color note`), *Frequency ranges / band plan* (`name lo hi step demod color kind note`), *Transmitters* (`name lat lon h freq erp_w pol azimuth beamwidth note`), *Receiving points* (`name lat lon alt h rx_ant rx_gain note photo`), *Links* (`name lat lon h lat2 lon2 h2 freq kind color label note`), *Antennas* (catalogue), *Antenna tests* (the same source with another antenna / height / site: `name t site lat lon ant h freq rssi snr note photo`), *Signal log*, *Track* and *Photo log*. Column names are the ones the rest of the app reads (the Map, Video Overlay, Mark Point, Source Locator, Radio Reach, Signal Paths, the Sequencer, the Band Scanner); each template proposes a folder (`field/`, `sources/`, `links/`…). Logic: `modules/table-templates.js`, `node tools/test-tabletemplates.mjs`.
- **Field rules** (▦ schema → Fields; `modules/table-rules.js`, `node tools/test-tablerules.mjs`): *record name* — a template like `{Surname} {Name}` for links and cards; *auto number* — the next number on every new row (the counter lives in the list and does not roll back after deletes; clearing the list resets it); *calculated* — a formula such as `[price] * [qty]`, `round([a]/[b],2)`, `if([x]>5,'big','small')` (own parser, no `eval`: operators, `?:`, functions `round floor ceil abs sqrt pow min max if coalesce concat upper lower trim len substr contains num text now year month day convert`; `convert([len],'km','mi')` changes units — the same names as in Unit Converter, also `C`, `F`, `m2`, `um`…); with *stored* the value is written to the list when the row is saved (frozen until it is edited or recalculated), without it the value is computed on load and never stored; *unique* — groups of fields separated by `;` (`Surname, Name; Phone`): a repeat is refused in the form and skipped for wired rows (an empty part of a group is ignored, case and spaces do not count); per field: *default* for new rows and *required*.
- **Lookup in another list** (calculated field; `modules/lookup-kernels.js`, `modules/table-lookup.js`, `node tools/test-lookup.mjs`): `lookup('list','key column',[Field],'result column'[,'mode'])` returns a value from another list by match, `between('list','from','to',[Field],'result column')` — from the row whose range contains the value (the narrowest wins). Modes: *eq* (default; case and edge spaces ignored), *mac* (keys are the start of an address — OUI `00:1B:C5` or 28 / 36 bit `00:1B:C5:0A:B`; separators do not matter, the longest key wins), *prefix* (`DJI-` → `DJI-MAVIC3`), *contains* (`cam` → `IPCAM_5G`; a scan, for short lists). List and column names are quoted literals; the list is named in full, or by its last part (`MAC vendors (OUI)`), or `presets/…` (built-in band plans work too). The list is turned into an index once (read page by page, SDR sound does not stutter) and shared by all nodes: a lookup is a hash / binary search — 200 000 OUI lookups take ~0.6 s. An error (no list, no column) is shown in the field's settings and the tooltip; when the source list changes (download, edit) the dependent tables recalculate by themselves. The value of a `[Field]` is not limited to MAC: any text or number from a wire (`rec`) works.
- **Reference lists** (`modules/reflists.js`; Files → «⇩ offline», small ones download themselves at the first start with a network; not synced between devices): `Reference/MAC vendors (OUI)` (IEEE MA-L / MA-M / MA-S, ~52 000 prefixes, from nmap-mac-prefixes; a copy is in `data/nmap-mac-prefixes`, so «⇩ offline» works without GitHub), and from [smittix/intercept](https://github.com/smittix/intercept) (Apache-2.0; copies in `data/intercept-*.json`, rebuilt by `python3 -I tools/intercept/build.py <intercept/data> data`): `Signals (intercept)` (~1000 frequency ranges with bandwidth and modulation, sigidwiki links), `WEFAX stations`, `Spy stations` (28 number stations and diplomatic HF networks, 135 frequencies, priyom.org; one row per frequency, `hz` for exact `lookup()`), `TSCM bands` (surveillance frequencies with risk), `Wi-Fi SSID patterns` (drones, cameras), `MAC prefixes (drones, trackers, cameras)`, `BLE trackers`. They are ordinary lists of Table — open, filter, edit, use as the source of `lookup()`. Preset: *Identify: Vendor by MAC, Signal by Frequency (Table lookup)*.
- **Output ports** (▦ schema → Fields, the **→** tick): which fields come out as wires. Old patches keep every field as a port until you touch a tick; after that only ticked fields have one (wires to unticked ports are removed). Under **⋯** of a *link* field, tick fields of the linked record (*linked record → outputs*): ports `Link.Field` give that field of the first linked record of the current row (read when the list loads or the ticks change). `node tools/test-tableports.mjs`
- **Rows**: `+ row`, ✎ edit, 🗑 delete, fields are added, renamed (click the name; the data stays), typed and removed in **▦ schema**; a `color` column is a colour picker, `demod` a mode list, frequency fields (`lo`, `hi`, `freq`, `step`…) accept `7.1M`, `433k`, `14 MHz`. A row shows on one line — colour, name, value (a frequency range as `7.0M-7.2M`). Click a row: it is selected and goes out. Lists of any size work, 300 rows are drawn (*tail* shows the last ones).
- **Columns view** (**▦ schema**, or *⋯ → Fields & colors…*; the panel stays open while you edit fields — one list: a **show** tick (card and column), name (click to rename; data stays), type, **⋯** for choices / link, format and width, **⧉ duplicate** and **✕ remove** (no question — an **Undo** note brings the field and its values back); drag a row to change the order; *Row colors* is folded): the list is a grid like a packet list in Wireshark — a sticky header, the row number, one column per field (layout *compact* brings back the old *name · values* look). Click a column header to sort by it (▲ → ▼ → off). Per column: show / hide, order (drag), format (`auto`, `text`, `hz`, `time`, `hex`, `num`, `swatch`) and width in px (empty — by content). `auto` shows frequencies as `7.1M`, time columns as `hh:mm:ss.mmm`, photo and audio columns as clickable icons. The view is saved in the patch.
- **Row colours**: rules *filter → colour* (the same syntax as the filter above: `err>0`, `proto:udp`, `level:warn`); the first matching rule paints the row. A row no rule matched gets the default colour (*otherwise colour by*): the `color` column → an error column (`err`, `error`, `crc_err`, `bad` not 0) → `level` / `severity` / `status` (`err…` red, `warn…` yellow) → a hue per value of the first of `proto`, `type`, `kind`, `mode`, `service`, `modulation`, `demod`, `class`, `category`, `dir`. The select also takes any column of your own, or *nothing*.
- **⛶ Expand canvas**: in the header of a module with a main canvas (spectrum, scope, waterfall…) and of Table. The parameters are hidden and the canvas (or the list) takes the whole module; the size of the module does not change and the ports stay. ⛶ again brings the parameters back. In a tile, ⛶ in the pane header does the same for Table: only the list tools stay.
- **Filter**: words from the start of any field (`20m` does not find `120m`), all words must match; `demod:am` — in one field (`a|b` — either, `to:` — the field is not empty, a leading `-` excludes: `-kind:ambe`), `lo>7M`, `step<=1000`, `name=FM` — comparisons. The filter limits the list on screen, what is played and the `bands` output.
- **Import / export**: `import` takes CSV, TSV, TXT (a line is a record), JSON (an array of objects, an object holding such an array, JSON Lines), KML, GPX, GeoJSON — several files at once, each becomes a list named after the file (in the current folder). `export` saves the list as CSV, TSV or JSON (the ⋯ menu); `export all` saves every list of the browser DB in one JSON file, `import` brings them back.
- **Records in**: the `rec` wire adds records (decoders, other tables, any source), `text` adds lines (a line is a record with a `text` field; with *text → columns* in the fields panel CSV lines go into the list's columns), new fields become new columns. Logging numbers is a separate node, **Value Log** (Output, `modules/vallog.js`, `node tools/test-vallog.mjs`): inputs `a–d` become a `rec` with a timestamp `t` and the *columns* names every *period* s, on a `trig` edge, or once with *Add row now* (save the current frequency as a bookmark); wire its `rec` to a Table (with a *key* column it updates a row instead). Old patches with *log inputs a–d* get a Value Log next to the Table. *max rows* (fields panel) drops the oldest rows (a log does not grow forever; in `@patch` at most 1000).
- **The settings are the columns' (and the list's), not the node's**: how a list takes records is set in the **fields panel** (▦ schema) and is kept with the list — in its schema, so it travels with copies, exports and backups, and every Table on that list behaves the same. A column has *key*, *text out*, *sort* (also a click on its header: ▲ → ▼ → off) and *from packet*; the list has *unique*, *max rows*, *text → columns*, *all packet fields*, *newest first*, *rows wire* (what a set on the `rows` input does: replace / add / sync / new only) and *first row selected at start*. The node has no settings of its own any more; the list scrolls after new rows by itself while it is at the end (with *newest first* it stays on top), and the status line shows only an error. Old parameters of the node (`key`, `textCol`, `maxRows`, `pfields`, `textCsv`, `rev`, `sortCol`, `sortDir`, `initial`, `rowsIn`) are moved into the list the first time it is loaded.
- **Upsert** (*key* on a column): with a key column set, a record from `rec` whose key already exists updates that row (non-empty fields win) instead of adding a new one, and the `count`, `first`, `last` columns are kept. One table per entity type (towers by `plmn-lac-cid`, subscribers by id…) gives a deduplicated list.
- **Packet fields** (*from packet* on a column): the column is filled from every wired `rec` before it is stored. The value is a path into the record (`a.b.c`) or a field of the record's `hex` parsed by its `hexSchema` (as in HEX Structure; with no `hexSchema` the schema is detected from the bytes), e.g. column `type` ← `mtype_name`, column `addr` ← `body.devaddr` for a LoRaWAN frame; *all packet fields* (list) adds every parsed field as a column. After you edit it, the rows already in the list are filled too (empty cells only, nothing is overwritten).
- **Time**: *▦ schema* → *time: UTC / local* sets how time columns (`t`, `time`, `ts`, `date`, or the *time* format) are shown; the stored values are not changed.
- **Keys**: `↑` `↓` `PgUp` `PgDn` `Home` `End` move the selected row of the list (click it first); the selection goes to the outputs as with a click.
- **Out**: one record at a time. Every column is an output port (a column named like a fixed port gets a `_`); `rec` carries the whole row as a record (for the map, Rec Log, **Graph**), `text` — the column marked *text out* (or the whole row), `row` / `count` / `next` (pulse per selection), `list` (the name of the active list). Nothing goes out until a row is selected; stepping through rows is Row Player. `rows` is the one list output: the records of all lists ticked in the tree (the active one and the others, with the common filter) as one set; it changes only when the lists do. Wire it to Graph, Map and Video Overlay `rows`, to another Table's `rows` input (stores the set), and to a Spectrum Analyzer `bands`, Signal Identifier `plan`, Channel / Band Scanner `bands` and `skip`: rows with `lo` (or `freq`), optional `hi`, `name` / `label`, `color`, `step` get numeric `lo` / `hi` / `step` / `label` / `color` added, and the receivers of frequency ranges take only the records that have a `lo`. (Older patches with the `bands` output are converted to `rows` on load.) `mid` and `span` of the selected row appear next to `lo` / `hi` / `step`. `sigs` takes the labels of a Signal Identifier, as the band plan did. The `rows` input stores a whole set (Internet Radio stations, another Table, any list of records) in the active list: *rows wire* — replace its rows (a new search replaces the old list) or add to them; new columns appear from the fields of the records. Raw packets work too: put them in a column (hex, text) and wire the port.

### Points on the Earth's surface

Everything that stands on or near the ground — airfields, runways, towns, peaks, **your own points** (transmitters, observation posts, test locations) — is a row in a Table list, so one set of points serves the map, the 3D overlay and the analysis.

- **Lists** (created by the loaders, editable by hand): `geo/airfields` (`id name icao iata kind lat lon ele src`), `geo/runways` (`id name airport lat lon lat2 lon2 width surface src`: both ends of the runway, `name` is the designator «09/27»), `geo/places` (`id name kind lat lon pop src`), `geo/peaks` (`id name lat lon ele src`). `src` says where a row came from (`ourairports`, `osm`, `builtin`, or `user` for your own). A row with a known `id` is never overwritten by a loader, so edits and deletions of columns stay; add rows with any `id` of your own.
- **Radius circles** (a `radius` field: GPS accuracy, estimate error): the Map's *radius circles* parameter — `all` (thin pale circles, only those on screen), `selected` (only the clicked object, brighter and dashed) or `off`. While the map is dragged the labels are not drawn, so panning stays smooth with hundreds of objects.
- **Your points**: any list with `name`, `lat`, `lon` (and, optionally, `h` — antenna / mast height above ground in m, `alt` — above sea level, `color`, `freq`, `erp`… any other columns). Wire the Table's `rec` or `rows` to the **Map** (labels are taken from `label`, else `name`, else `id`; a runway with `lat2` / `lon2` is a line) and type the list name into *Video Overlay → own points* to see the same points in 3D at their real height over the terrain.
- **Where the data comes from**: *Video Overlay* (*airfields*, *towns*, *Download area for offline*) and the *OSM* option fill the lists around the camera; *Flight Sim → start: nearest runway* reads `geo/runways`. Terrain tiles stay in the browser database too (Horizon), apart from the tables.
- The trash button in the toolbar only **refreshes the app files** (cache, service worker): lists, patches, terrain and every other kind of data are never erased by it. To keep a copy or move to another browser use **Settings → All data → Export… / Import…**: one `.dspbackup` file with the patches and settings, all Table lists, terrain and map caches, samples, tracker sessions and the spectrum archive, in groups you tick; an import replaces records with the same key (a Table list is replaced as a whole), erases nothing and reloads the page. Logic: `modules/geostore.js`, `modules/backup.js`, `node tools/test-backup.mjs`.
- **Sync between devices** (**Settings → Sync devices → Sync…**): the file storage (Files, Audio, Images) and the records of every Table list are kept the same on all devices that share one key; the newer edit wins, a deletion is passed on and does not come back, folders are created as needed, the column setup of a list travels with it. Not synced: patches and settings, terrain and map caches, the spectrum archive, tracker sessions (use Export / Import for those); ids of files differ between devices, so a patch that points to a file by id keeps pointing at the local id. How it works: *New key* makes a 128-bit key of the pair; **Save to Google account** puts it into Chrome's password manager (Credential Management API), so the other device signed in to the same account gets it with **Get from Google account**; as a fallback *Copy link* gives an address with `#sync=<key>` for “Send to your devices” and the key can be typed in. The key derives the room and the cipher of the connection offers that two devices exchange through an MQTT broker over WebSocket (default `wss://broker.emqx.io:8084/mqtt`, any public or own one: the broker sees a hashed topic, addresses and timing, not the content); the data itself goes straight between the devices over WebRTC (a STUN server is needed unless they are on one network; no TURN, so some mobile networks will not connect). More than two devices connect each to each. Both devices have to be open at the same time; a file larger than *largest file* is skipped. The key stays out of the `.dspbackup` file. **Sync Data** (Sources): a text channel for the graph over the same link — a second WebRTC data channel (`app`) next to the file one. Each device has a name (Sync devices → *Name of this device*); `send` goes to *all devices* or to the one picked in *send to* (the `to` input overrides it with a name); `line` / `go` / `rec` (JSON becomes records) / `from` (sender) / `count` / `devices` come out. The *channel* name keeps different uses apart: a node takes only messages of its own channel. Not only text: `sendFile` (a Files id — a video, a recording, an IQ file…) or the *Send file…* button send a file, `img` sends the graph's pictures as PNG (no more often than *imgGap*), `rec` sends records as JSON; on the other side `file` (id in the Received folder of Files / Audio / Images), `got`, `img` and `rec` come out. Files go over a third channel (`file`) with the file-transfer core `modules/xfer-kernels.js` (the same wire format as the file channel of WebRTC Data; `node tools/test-xfer.mjs`): a file is refused before its content is sent if it is over *largest file* or no Sync Data with that channel name is open. Live video is not streamed this way (send a recorded file; a live picture goes as a stream of PNG frames at most). Works while the sync is on and the devices are connected; presets **Sync: Chat Between Your Devices** and **Sync: Files, Video and Pictures Between Devices**.
- **Sync Video Out / Sync Video In** (Output / Sources, `modules/syncvideo.js`, format in `modules/mjpeg-kernels.js`, `node tools/test-mjpeg.mjs`): live picture over the same sync link as **MJPEG**. Out takes `vid` (camera, video file) or `img`, makes JPEG frames (*fps* up to 25, *max width*, quality *wish*, *target frame size*) and sends them to *all devices* or the chosen one over a separate data channel without retransmits (a busy channel skips the frame, a lost frame is not resent, an older frame never replaces a newer one); the JPEG quality lowers itself when frames are bigger than the target. In with the same *stream name* outputs `img` (width 160 – 640), `active`, `fps` and `from`; only the newest frame is decoded. Several streams at once — different names. Not sound: for a voice use WebRTC Audio Out / In on a WebRTC Data connection. Preset **Sync: Live Video (MJPEG) Between Devices**.
- **Voice and video in packets** (`modules/media.js`, format, jitter buffer and framing in `modules/media-kernels.js`, `node tools/test-media.mjs`): four nodes that turn sound and picture into messages of the `bin` wire and back, so *any* channel that carries `bin` can carry a call — Sync Data between your own devices, MQTT, Packet Link (WebSocket, serial, BLE UART), and through a radio modem. **Voice → Packets** (microphone or any sound, `ptt` input, *send only above* gate so pauses cost nothing): **Codec 2** 1.6 / 3.2 kbit/s (for radio: 8 bytes per 40 / 20 ms; the codec2.wasm of the Vocoder), **Opus** 6–32 kbit/s (WebCodecs; conference quality), **μ-law** 64 kbit/s (works in every browser); *frames per packet* trades delay for header overhead. **Packets → Voice**: a jitter buffer (*delay to smooth the link*, at least 1.5 packets) puts packets back in order, hides a lost packet with a faded repeat, drops late ones, never lets the queue grow, and starts over when the sender restarts; outputs `lost` and `buf`. **Video → Packets**: JPEG frames from `vid` / `img` (*fps* from 0.1 to 25, width 64–960, quality wish, target size, grayscale) — a slow-scan picture over a few kbit/s or a 25 fps stream; **Packets → Video** shows the newest frame (`img`, `fps`). A packet is 5 header bytes (codec, stream name, number, frames) + the codec frames; several streams share a link, each receiver takes its own *stream name* and kind. *Framing* (none / len8 / len16be / slip / kiss / cobs) wraps a packet for a byte stream (serial radio modem, KISS TNC, BLE UART): set the same *frame* in Packet Link, which cuts the stream back into packets (checked against its framers). Sync Data takes and gives `bin` as datagrams (channel *conf-…*, a lost one is not resent, up to 200 KB). Presets **Conference: Voice and Video Between Your Devices (Sync Data)** and **Voice and Video over a Byte Link (KISS / SLIP, no hardware)**. Checked in headless Chromium: all four codecs through the nodes (a 440 Hz tone comes back at 440 Hz with Opus and μ-law, Codec 2 as a vocoder tone), a picture with a QR code read back from the received JPEG, voice + video through two Sync Data nodes with an in-page device, KISS / SLIP through Packet Link; real microphones, cameras, two devices and a radio modem have not been tried. Codec 2 is built here with the modes 3200 and 1600 only (700C / 1200 need a rebuild of `vendor/codec2.wasm`). Logic: `modules/sync-kernels.js` (merge, protocol), `modules/sync.js` (storage, connection, dialog), `node tools/test-sync.mjs`. Checked in headless Chromium with two profiles and a local broker (records, a file in nested folders, column setup, edit, deletion of a record and of a file); the account password manager and real phones have not been tried.

### Terrain height, more layers, vector files, open data

- **A point with the height map** (answer to «how do I add a point that knows the terrain»): a tap on an empty spot of the **Map** shows `ground: N m` (terrain height above sea level at that spot) and the `pick` record carries `ground`. Wire `pick` (or any record with `lat` / `lon`: a *Table* row, *Mark Point*) through **Point Elevation** (Geo): it adds `ground` and, from `h` (height above the ground, m; the `height above ground` parameter fills it when a point has none), `alt = ground + h`; a record with `alt` (GPS, above sea level) and no `h` gets `h = alt − ground`. `force` recalculates `alt` even when it is set. Wires `lat` / `lon` give the numbers `ground` and `alt`. The heights are the Terrarium tiles that *Horizon* uses (one download, kept in the browser; with *download missing terrain tiles* off only the saved ones are used). In a **Table** list, *🌐 open data → ⛰ Fill ground elevation* adds the column `ground` for all rows with `lat` / `lon` (and `alt` / `h` where those columns exist and are empty).
- **Vector base map** (Map, `modules/mvt-kernels.js`, `node tools/test-mvt.mjs`): `tiles` = *OpenFreeMap (vector)* / *OpenFreeMap Dark (vector)*. The node loads Mapbox Vector Tiles (OpenMapTiles schema: land cover and use, parks, water, waterways, buildings, roads by class with casings, railways, borders, place and water names), decodes the protobuf itself (no libraries) and paints each tile once into a 512×512 picture, which then goes down the raster path (memory cache, smooth zoom, the parent tile while a new one loads). Lines and text stay sharp, a tile is far smaller than a PNG, and no raster server is needed. The tile address comes from the server's TileJSON (it carries the build date; refreshed every 6 h, the last good answer is kept in the cache); viewed tiles go to the same Cache API as raster ones and open offline (there is no bulk download, no «⇩ offline» item). Above zoom 14 the picture is stretched. Part of the *spare map* mechanism below (vector → CARTO). Preset *Map: Vector Base Map (OpenFreeMap) — Sharp at Any Zoom, Light and Dark*. Checked in Chromium with stubbed server answers (a real OpenFreeMap tile was not reachable from here — styling on real data is not seen yet).
- **Spare map when a tile server refuses** (Map, `modules/geotiles-kernels.js`, `node tools/test-geotiles.mjs`): public servers answer 403 / 429 (OSM policy, limits, blocks by Referer) and the base map goes blank. After 4 failed network loads in a row the source counts as down for 5 minutes and the node draws a spare one (OSM → OSM Humanitarian → CARTO Light → OpenTopoMap, and so on; satellite is not replaced by a street map), with a note on the map: `tiles: OSM HTTP 403 → OSM Humanitarian`; then it tries the original again. Offline failures are not counted, tiles already in the cache still show. Checkbox *tiles: if the server refuses…* (on by default) turns it off. Checked in Chromium with a stubbed 403.
- **More maps and layers** (Map): `tiles` — OSM, OpenTopoMap, OSM Humanitarian, CyclOSM, CARTO Dark / Light, Esri Satellite / Topo / Streets, **Relief (DEM)** (hypsometric colours with shading, drawn from the same terrain tiles — no extra server) or `custom` (a URL with `{z}/{x}/{y}` in advanced). `overlay` — Hillshade (DEM or Esri), Railways, Sea marks, Hiking trails, Cycling routes or custom — drawn over any base with the `overlay opacity`. Everything viewed is cached for offline use; the attribution of the active layers is shown in the corner. Tile servers have their own usage policies — bulk downloading is not done.
- **Vector layers** (Map): *Load vector layer* takes **GeoJSON, KML or GPX** — lines, polygons (with holes) and points. Colours come from `stroke` / `fill` / `fill-opacity` / `marker-color` properties (otherwise a palette); points become ordinary map objects with their properties. The layers are kept in the browser and restored with the patch (only their names are in it); *Remove vector layers* clears them. Shapefile / GeoPackage must be converted to GeoJSON first.
- **Open data → Table** (button **🌐 open data**; the area is «lat, lon, radius km» or `view` — what the Map shows): **cell towers** from OpenStreetMap (Overpass, no key; masts tagged as mobile / GSM / UMTS / LTE / 5G), from **OpenCelliD** (`getInArea` with your free API key, kept in this browser) or from an OpenCelliD **dump file** (`cell_towers.csv` / `.csv.gz`, read as a stream and filtered by area and MCC — nothing else is kept in memory). Rows go to `geo/towers` (`id name operator kind radio ref lat lon h ele mcc mnc lac cid range samples updated icon radius src`; an OpenCelliD estimated `range` becomes the `radius` circle on the Map), a known `id` is never overwritten. Also: broadcast FM / TV masts, all communication masts, amateur radio repeaters (`geo/repeaters`), peaks (`geo/peaks`) and **your own Overpass query** (`{{bbox}}` is replaced by the area; columns come from the tags found, → `geo/osm`). The Map has the same for the visible area (*objects from OpenStreetMap → Load objects in view*): the objects appear on the map at once and are saved to the list. OSM coverage of towers depends on volunteers; OpenCelliD positions are crowd-sourced estimates, not surveyed sites. The Overpass servers are shared — requests go one at a time with pauses. The kernels are checked by `node tools/test-geodata.mjs`.

- **Signal Paths** (Radio): what paths a radio signal can take between two points. The ends are `lat` / `lon` and `lat2` / `lon2` (wires, *My Position*) or one record with both (a *Table* row: `lat lon h lat2 lon2 h2 freq name`, which also overrides the parameters *h*, *h2*, *frequency*); the terrain is the *Horizon* height map (both points must lie inside its radius; without Horizon the ground is flat at *ground height*). **Direct path**: line of sight over the terrain with the curvature of the Earth (*k*), how much of the **first Fresnel zone** is clear (≥ 60 % is the usual target), the **diffraction** loss on the main obstacle (knife edge, ITU-R P.526) and the total loss with the free-space part. **Reflections**: the single specular reflections off the terrain — the point where the reflected ray from one end hits the other (a grid search, then refined with the mirror-image method), kept only if both legs run over the ground; a flat ground gives the ground bounce in the middle, a steep slope gives a reflection off the slope. For each path: the reflection point, extra length and **delay** (ns), level against the direct path (*reflection loss* is a parameter: 8 dB rough ground, 2…6 dB water or smooth ground); *tolerance* is how far (m) the reflected ray may miss the other end, *longest path ÷ direct* limits how far off the axis a reflector may be. The tile shows a **side view** (terrain with the curvature, Fresnel zone, direct path coloured green / yellow (Fresnel < 60 %) / red (blocked), reflected paths dashed with their lateral offset) and the numbers. **Out**: `rec` — the paths as **links** (the direct one with `alt` / `alt2`, `loss_db`, `fspl_db`, `diff_db`, `los`, `fresnel`; the reflected ones as `path3` through the reflection point with `rel_db`, `delay_ns`, `excess_m`), once per calculation — wire to the Map, to Video Overlay `rec2` (3D, free camera) or to a Table; `loss`, `los`, `fres`, `dist`, `n`, `spread` (the largest delay of the reflections within 20 dB of the direct path, ns) as numbers. *Save to table* keeps the links in `analysis/paths` (`path3` as JSON text — Overlay and the Map read it back). Single reflections only (no double bounces, no vegetation, buildings or diffraction on the reflected legs). Preset *Signal Paths: Direct and Reflected Between Two Points*. Logic: `modules/paths-kernels.js`, `node tools/test-paths.mjs`.
- **Coverage Map** (Radio): a preliminary calculation of where the signal of your transmitters is weak or absent. Transmitters are Table lists in *transmitters* (`name lat lon h freq erp_w azimuth beamwidth`; the *Transmitters* column template) and/or records on `rec` (accumulated by `name`; *Forget transmitters from rec* clears them); `azimuth` + `beamwidth` give a directional lobe (−25 dB at most), `freq` empty → *frequency*; *only these* filters by name or frequency. The terrain is the *Horizon* height map (the radius must fit in it); for every cell of the grid (*cell*, 0 = auto, ~120 across) and every transmitter the path loss is: free space + **diffraction** over the terrain (Deygout, up to 3 edges, curvature with *k*) + optional **two-ray ground interference** on line of sight (lobes and nulls), + *extra loss* (buildings, trees). The level is ERP + 2.15 dB − loss + receiving antenna gain (*rxgain*, *rxh* height). The map shows the strongest signal (or the number of signals above *receiver sensitivity*); cells below it are **dead zones** — their percent and area are in the readout and on `dead` / `area`, and their edge goes out on `poly` as dashed `path` records for the Map. **Field comparison**: *field measurements* is a Table list (`lat lon rssi` dBm, `h`, `tx`, `freq`); every point is calculated from its own transmitter (the `tx` column) or the strongest, the readout shows **bias** and **rms** (measured − calculated, dB; `bias` / `rms` / `n` outputs); `rec` carries a summary and a *residual* record per point (blue — stronger than calculated, orange — weaker); *Save residuals to table* → `analysis/coverage`; *Calibrate* removes the bias through the extra loss (never below 0). **Raster on the Map**: the `raster` output is a coverage image (strongest signal, or the count above the threshold; cells without terrain are transparent) with its lat / lon bounds — wire it to the Map (`rec` / `rec2` / `rec3`) and it is drawn under the objects and over the tiles, with the *raster opacity* of Coverage; a record `{kind:'raster', id, canvas, north, south, west, east, opacity}` from any calculator works the same way (`gone` removes it; *Clear* clears rasters too; they are not saved with the points). Preset *Coverage: Transmitters from Table → Dead Zones*. No buildings, vegetation or reflections off the terrain (see Signal Paths for two-point reflections). Logic: `modules/coverage-kernels.js`, `node tools/test-coverage.mjs`.
- **My Position** (Geo), GPS mode: the browser decides where the position comes from, and it alternates between satellites (≈ 3–10 m under open sky) and a Wi-Fi / cell estimate (30–100 m and worse), so the readout now shows the raw accuracy of the last fix, the best one of the last minute and what it most likely is, and after 40 s without anything better than 30 m it says why (indoors / no sky view / a cold start takes 1–3 minutes / coarse location only; where to switch on precise location; or take the raw GNSS from the DSP / Termux app via Phone sensors). *Ignore fixes worse than … m* waits for a good fix and keeps the last good one meanwhile; *average the last … s* takes the mean of the fixes with the weights 1/accuracy² (the reported accuracy is the median / √N with at most ~10 independent fixes counted; the random error falls, a systematic one does not) — the averaged fix is what `lat`, `lon`, `acc` carry to Site Plan’s «＋ GPS fix» and Plan Editor. Kernel: `modules/geofix-kernels.js`, tests: `node tools/test-geofix.mjs`.
- **Site Plan** (Geo): a plan of a plot or a building from field measurements, in 3D, for outdoor first. Measurements are text, one per line: `A-B 12.4` (tape along the ground), `A-B h 12.4` (horizontal), `A-B dz 1.2` (B is higher), `A-B az 45` (compass), `A-B-C 90` (angle at B), `A-B tilt 25 15 eye 1.6` (clinometer: 25° up from 15 m away, eye height → height of B), `A z 120`, `A gps lat lon ±3` (several fixes are averaged by weight), `A at x y`, `poly A B C D` (area, surface, perimeter, slope), and the short form for a room: `room Hall 4.48 3.74 4.46 3.74` — the sides in walking order, the corners are named Hall1, Hall2… by themselves (side *i* runs from corner *i* to *i+1*, so the first wall is Hall1-Hall2) and every corner is 90° unless written: `3.74/95` is a 95° corner at the end of that side, `3.74/?` an unmeasured one (then add a diagonal: `d 5.8` is Hall1-Hall3, `d2` Hall2-Hall4); the corner names work in ordinary lines too, and rooms are joined across a wall with `wall Hall2-Hall3 Kit1-Kit4 0.4 [shift s]`: the side Kit1-Kit4 of one room faces the side Hall2-Hall3 of the other behind a 0.4 m wall, Kit1 opposite Hall2 (or `shift` metres further along the wall, negative — back), Kit4 towards Hall3; rooms are kept from overlapping. Names are case-sensitive (`zal2` is not `Zal2`; the readout says so). A tape and angles cannot tell a plan from its mirror image (whether the rooms were walked clockwise or not), so a plan without a compass or GPS may come out flipped: the ceiling height goes at the end of a room (`room Hall 4.48 3.74 4.46 3.74 h 2.65`, or `poly … h 2.65`) or once for all rooms (`height 2.7`): the readout adds the volume and Plan Editor gets it as the height of the room’s walls; windows and doors go into a side of a room: `window Hall1-Hall2 1.20 1.40 h 1.45 sill 0.85` is 1.20 m from the corner Hall1 to the near edge, 1.40 wide, 1.45 high, the sill 0.85 above the floor (`door …` — h 2.05 and no sill unless written); they are drawn on the plan. The walls are built from the rooms (kernel `spWalls`): the tape gives the inner faces and the walls stand outside them — where another room's side faces this one closer than 0.8 m, one shared wall fills the gap (its thickness is the gap), elsewhere the outer wall (`outer 0.45`, 0.4 m by default) with the corners closed, so the plan is one closed structure without holes or overlaps (a wall end that runs into another wall is cut at its face and a filler inside a junction is dropped — an overlap would make a ray through the junction cross two walls and count the loss twice; a gap between faces that are not quite parallel takes its widest point, so no sliver is left open); the outer face was never measured (it is the assumed thickness), so outer faces that nearly line up (parallel, < 8 cm apart) are put on one line by adjusting each wall’s thickness — the facade is flat and the inner faces stay at the measurement; an opening goes into whatever wall stands there, so a door written from either room cuts through the shared wall (written from both — still one). Materials: `outer 0.45 concrete` (the shell), `inner drywall` (the shared walls; the shell’s material if not given), `material Zal4-Zal1 glass` (the wall on that side of a room, outer or shared) or a material at the end of a `wall` line — `brick concrete block drywall wood glass metal` (block — aerated concrete, 3 dB per 10 cm at 2.4 GHz) or in Russian (`кирпич бетон газоблок пеноблок гипсокартон гкл дерево брус стекло металл`); the readout sums the wall lengths by kind and material. Site Plan draws the walls coloured by material and sends them to Plan Editor as one `plan walls` record with the openings (the set replaces the previous one: walls move in place, removed ones go) and the rooms as contours without walls of their own; there the doors and windows count in the wall loss of the signal; floors: `level 2 [z 2.95]` starts a floor (the rooms below it in the text are on it; without z it stands on the highest floor so far + its room height + the slab; `level cellar z -2.2` — a cellar), `same A B` puts corner B exactly above / below corner A (two corners fix a floor, one leaves it free to turn), `slab 0.22 concrete` — the floors between levels; walls are built per floor, the outer walls under an upper floor rise through the slab; `roof gable|hip|shed|flat [angle] [overhang 0.5] [ridge long|short] [level NAME]` — a roof over the top floor (or that one) on the outer faces of its walls, the readout gives the slope area and the ridge / eaves heights; the plan shows one floor (*level on the plan*, the others dashed) and the roof edges dashed; the plot: `fence A B C … [h 1.8] [sheet|mesh|wood|brick|concrete|block] [closed]` (Russian names too: профлист, рабица, штакетник…) is a fence — a wall for the signal (corrugated sheet ≈ 20 dB and a metal reflector, chain-link mesh ≈ 3 dB, nothing above its height); `road A B … [w 3.5] [asphalt|gravel|tile]` and `area A B C … [grass|asphalt|gravel|tile|garden|water]` colour the ground (the readout sums the fence length and the areas); outbuildings are rooms; `source NAME POINT [h 25] [eirp 43] [f 1800] [az 120] [bw 65]` is an outside transmitter above a point (a cell tower sector, a neighbour’s router; the point by GPS, `at` or tape) — Plan Editor gets it as an external antenna that does not stretch the coverage map; a line `mirror` turns it left ↔ right (ignored when a compass, GPS or two `at` points already fix the sides). A contour has a mirror twin with the same lengths and angles (a corner flipped across the diagonal into a folded «bow tie»): the order of `poly` picks the unfolded one, and an under-measured corner is amber with the missing measurement suggested (`D-A (length) or C-D-A (angle)`). `± σ` on a line overrides the default error (tape, compass / angle, GPS — in the parameters). The solver is a weighted least-squares adjustment (Levenberg–Marquardt): a tape shapes the plot, GPS places it, the compass turns it, each by its error; a point's error is shown, a weakly determined one is amber, a mistyped number turns its edge red and is named in the readout (the diagonals give the redundancy that exposes it). The view is a plan or a 3D model: drag to turn it (a finger or the left mouse button), two fingers or the wheel to zoom, the right button or shift+drag to move, double click to reset; the *grid* is either north-aligned (E / N from the origin) or *structure* (axes along the first side of the contour from its first point, the plan is drawn turned that way), with coordinates on the axes and optionally on every point. `lines` takes measurements as text from Photo Measure and Clinometer, `table` names Table lists with measurements — columns `kind` (`d h dz az tilt ang poly`) + `a b c` + `value` [+ `sigma`], or `name lat lon [acc alt]`, or `name x y [z]`, or a ready `line` — and the same rows work on `rec` (play rows, Measure Entry records); *Points to the Table list* writes the solved points back (name, x, y, z, ± error, lat, lon); `rec` takes GPS fixes (`name lat lon acc alt`), *＋ GPS fix* appends My Position as a point, *GPS points take height from Horizon* adds the terrain height. A plan with two GPS points (or one plus an azimuth) is georeferenced: points and contours go to the Map (`rec`, `poly`); every contour also goes out on `rec` as a `plan poly` record, so wired to **Plan Editor** it becomes walls (set their thickness and material there — the wall loss of the antenna signal depends on both) and a room (preset «Site Plan: Room from a Tape Measure → Plan Editor Walls and Wi-Fi») and to *GeoJSON*; *DXF* (3D), *SVG* (dimensioned) and *CSV* (points ± error) work for any plan. Kernel: `modules/siteplan-kernels.js`, tests: `node tools/test-siteplan.mjs`. **Plan in a file:** a path in Files (`Plans/dacha.txt`) in the `file` parameter or on the `file` pin — the measurements are read from the file, edits are written back after a second (a new name creates the file), and changes made to the file in Files are picked up. The plan text is never kept only in the patch: the first edit creates `Plans/siteplan-DATE-TIME.txt` in Files (parameter *file*) and every later edit is written there after 0.8 s (*file* / *fsave* turn it off or point it elsewhere).
- **Measure Entry** (Geo): typed measurements for Site Plan. Choose what is measured (tape side, horizontal, height difference, compass, angle, clinometer, height of a point), the point names and the value — a number or an expression like on a calculator (`12.4+3.6*2`, `sqrt(3^2+4^2)`, `hypot(3;4)`, `sin cos tan atan` in degrees, `pi`, `^`, comma decimals) — and press *＋ Add*; or wire `v` (a number) and `go` (a pulse) from **Number Pad** (`out`, `enter`) / **Pocket Calculator**, or from **BLE GATT** (`value`, `new`) for a Bluetooth laser meter. *Chain* makes the next side start where the last one ended (names A, B, C … Z, A1 …), so a perimeter is walked with one number per side; *Close the contour* adds the `poly`; the log is editable text with *Undo*. Outputs: `lines` (the whole log, to Site Plan) and `rec` (the new measurement as a record `kind a b c value sigma line` — to a Table to keep the history, or to Site Plan’s `rec`). Presets: «Measure Entry: Walk a Plot with a Tape…», «Laser Distance Meter (BLE) → Measure Entry → Site Plan» (the Leica DISTO GATT service from its published description, not tried on a device; any meter that notifies a number works with its UUIDs, format and scale in BLE GATT), «Site Plan: Points and Measurements from a Table». Kernel: `modules/measureentry-kernels.js`, tests: `node tools/test-measureentry.mjs`.
- **Echo Ranger** (Geo): a tape measure made of sound. The phone plays a chirp (default 2–10 kHz, 30 ms; output `chirp` → *Sound Card*) and listens (input `mic` ← *Microphone*, echo cancellation and noise suppression off): a matched filter (correlation with the chirp itself) compresses it into a short peak — the impulse response of the room. The strongest peak is the direct sound speaker → microphone (every delay of the audio path sits in it and cancels), the later peaks are walls and furniture at c·Δt/2 (c from the air temperature); a band B resolves c/2B (8 kHz — 2 cm), several chirps are averaged. *▶ Measure* (or a rising edge on `trig`) takes *bursts* chirps and sends `dist` (the nearest or the strongest echo), `db`, `snr` and a `go` pulse — wire them to *Measure Entry* `v` / `go`, so a wall becomes `A-B 2.50` in the Site Plan log; `rec` carries every echo. *continuous* keeps chirping like a sonar; *simulate* (`2.5:0.4, 4.1:0.2`) replaces the microphone with a computed room to try the chain without hardware. Echoes closer than *minDist* (0.3 m, the side lobes of the direct sound) are ignored; the plot shows the impulse response in dB against distance with the echoes marked. Accuracy ≈ 1–2 cm to a flat wall at 1–5 m when the phone faces it squarely; soft surfaces and furniture give weak or false echoes. Kernel: `modules/echorange-kernels.js`, tests: `node tools/test-echorange.mjs`.
- **Room Walk** (Geo): a room from one spot. Point the phone at a wall — *Echo Ranger* `dist` gives the distance, *Orientation* `az` the compass azimuth — and press *＋ Wall shot* (or let Echo Ranger’s `go` pulse do it); turn to the next wall. A shot is a wall line perpendicular to its direction at that distance; the corners are where neighbouring walls cross, so 3–4 shots give the area, the perimeter, the sides and the standing point’s place, and `lines` carry the corners (`R1 at x y ± error`, the error from the distance and the compass errors) and the contour to Site Plan. *rectangular room* snaps the walls to one angle + 90° steps (the compass is noisy, the walls are straight) and shows how the room is turned from north; shots within *merge* ° are one wall and are averaged. Shots are editable text («azimuth distance» per line) with *Undo*; the plot shows the walls, the corners and the standing point; it warns when the point comes out outside the room (swapped azimuths / distances) or two neighbouring walls are nearly parallel. The phone must face the wall squarely. Kernel: `modules/roomwalk-kernels.js`, tests: `node tools/test-roomwalk.mjs`.
- **Plan Editor** (Geo): an editor for a plan and its 3D model, on top of Site Plan. One canvas, one orbit camera: *plan* (north up) or *3D* (drawn with a z-buffer: every pixel takes the nearest face, so the order of the objects never matters and even intersecting volumes look right; cameras see by height: the line of sight to a target (*target height* above the floor of the shown level: 1 m — a person, 1.6 — a face, 0.5 — a number plate) is blocked by a wall, fence or box only where it passes within their height (a pole camera sees over a low fence, with a shadow strip behind it), chain-link mesh and glass walls are transparent, a window only within its opening, a slab hides the next floor; a selected camera shows *the view from it* — a 3D picture from its position, azimuth, tilt and field of view in a corner window (tap — large); *reflections* (image method): 0 — the direct ray, 1 — plus one bounce off a wall face (default), 2 — plus two; a bounce point must be on the solid part of the face (an open door / window passes the ray), every leg loses through the walls it crosses, a bounce costs by the material (metal 1, concrete 5, glass 6, brick 7, block 8, wood 9, drywall 11 dB), and the paths add as powers; on the «signal» layer the rays to each receiver are drawn (direct solid, single bounces dashed blue, double violet) and the readout gives the direct level and what the reflections add; while dragging the map is computed with one bounce at most; *level*: all (3D — the house above the ground with the roof and the slabs, plan — the ground floor) or a floor number (3D — it and the ones below, a cut-away; 0 — ground, −1 — cellar); the signal counts a wall only where the ray passes through it in height, an opening only within its height, adds the loss of a slab when the ray goes from floor to floor, and the coverage is computed 1 m above the shown floor; walls are coloured by material (brick, concrete, aerated block, drywall, wood, glass, metal) in 3D and in the plan; the tool strip has drawn icons; *measure* (ruler) takes two clicks and snaps to wall corners and faces, then to points (Esc clears it); room labels show the name (from Site Plan: zal, kor…) and the area, only the name on the «signal» layer; *points: auto* hides the helper points (wall ends and room corners from Site Plan); lines are drawn only on real edges — where the face turns or the depth jumps — so walls that meet in one plane (corners, the lintel over a door, a shared wall) look cast in one piece; the picture is coarser while you drag and finishes crisp) (drag the empty space to turn, wheel / two fingers zoom, right drag or shift moves, double click fits); selecting, dragging and adding work the same in both — the ray from the cursor falls on the floor or on the object’s height. - **Photo Measure** (Geo): measure from a photo with a ruler in the frame. Smoothing, a level offset and a sign flip (iPhone) are parameters. The `line` output (`E-R tilt 27.5 20 eye 1.6`) goes to Site Plan.

### Timeline

**Timeline** (Analysis): rows of a Table drawn as intervals on a time axis — for airtime analysis (who transmitted on which frequency, how often and for how long) and, with the same columns, as a clip arranger. The storage stays the Table: wire its `rows` (or `all`) to the Timeline; the Timeline gives out the selected rows and the measurements and, when clips are edited with the mouse, the rows with the changes (`edited`) to write back into the Table. It also mixes the audio of clips, replays IQ clips, has markers and takes live events.

- **Row = event**: a start (`t`, `time`, `ts`, `start`…), a length (`dur` / `duration` / `airtime`, or an end column `end` / `t1`; without them the event is a point), any other columns are free: frequency, subscriber, packet type, `rssi`, `file`. The time unit is recognised by size (epoch milliseconds / microseconds, small numbers are seconds) or set by hand. Columns are found by name or set in the advanced parameters.
- **Lanes** by a column or several (`freq,src`: one lane per pair); **colour** by another column (packet kind); **bar height = rssi**; **filter** `kind=req,ack src=A* rssi>-70 freq!=433.92 name~regex word` (all terms must match; the `filter` input adds to it).
- **Transmissions**: *merge packets closer than, ms* glues the packets of one lane into one air transmission; everything below is measured on transmissions.
- **Measurements** per lane (and over the whole selection): count, **period** (median start-to-start; min / max / mean), **duration** (median / min / max), **duty**, rate, idle, **jitter** (spread of the repeats relative to the period), `ok` (share of intervals that are a whole multiple of the period within *period tolerance* — a repeat even if some were skipped) and `miss` (skipped repeats), rssi. *Reference events* (a filter such as `kind=req`) add `lag`: the time from a reference event to the next event of the lane (a reply to a request), its spread and count. *Link by column*: select an event — every event with the same value (a subscriber, an address) is outlined on all lanes.
- **Mouse**: wheel — zoom around the pointer, drag — pan, **drag the ruler** — move the playhead, **Shift+drag** — measure a span (the numbers and outputs then cover only it), click an event — its fields, the interval from the previous start and the pause, click a lane name — only that lane, **double click** an event — play from it, double click an empty spot — fit all, Shift+wheel — scroll lanes. *Follow the end* keeps the view on a Table that is still collecting live packets.
- **Playback**: *Play* (or Space) moves the playhead (speed ×0.1…64, loop, or loop within the selection); the `at` input sets the playhead from outside (seconds from the first event). Events that start under the playhead go to `rec` (all columns plus `_t`, `_dur`) and `file`. With *play audio files of events* an event whose `file` column holds an id or a name from Files is played by the browser (audio / video files, cut at the event length, optional `off` column — start offset, s). For mixing and IQ see *Clips: mix and IQ*.
- **Editing clips** (*edit clips with the mouse*): drag a clip — move it in time and to another lane (the lane column(s) of the row get the lane's values), drag its edge — length, **Alt+drag** — copy, **Ctrl+click** — add to the selection, Ctrl+A — all, Delete — remove, Ctrl+D — duplicate after the selection, arrows (Shift — ×10) — nudge, **double click on an empty spot** of a lane — a new clip (*length of a new clip*), **Ctrl+Z / Ctrl+Y** — undo / redo (the canvas must be focused: click it), *Set a column on the selected clips…* — `file=beep.wav`, `gain=-6`, `fade=0.2`, any column. While dragging, edges **snap** to the ruler grid, edges of other clips, markers and the playhead (Shift — without snapping). The Table stays the storage: the changes lie over its rows (in the patch parameter `edits`) and go out of **`edited`** (all rows with the changes) and **`diff`** (only the changed ones: `_op` = set / add / del, `_key`). To write them back wire `edited` into a Table (*rows in* = sync, a key column `id`); when the Table has accepted a row the overlay of that row is dropped on its own. The edits are matched to the rows by a key column (`id`, `key`, `uid`, `uuid` or *key column* in the advanced parameters; a new clip gets a unique value in it), without it by the row number — then wire `edited` into a separate Table. The time is written back in the units of the columns (`t`, and `dur` or `end`; a point event gets a `dur` column when it is resized). *Export rows with edits (CSV)* saves the same rows.
- **Clips: mix and IQ**: with *mix clips to the audio output* the audio / video files of the clips under the playhead are mixed lane by lane into the mono **`audio`** output (wire it to a Sound Card, a Recorder or any filter): row columns `off` (start in the file, s), `gain` (dB), `fadein` / `fadeout` / `fade` (s); *mix level* in dB; at speed ≠ 1 the pitch follows the speed. **Lane effects** (*lane effects*): a line per lane, `Voice*: gain=-6 lp=3000 hp=150 echo=250,.4 mute solo` — a name with `*`, gain in dB, low-pass / high-pass in Hz, echo (delay ms, feedback), `mute`, `solo` (the other lanes go silent); the lane tags `M` / `S` / `fx` show in the lane label. With *replay IQ files of clips to the iq output* the IQ recording in the `file` column (cu8 / cs8 / cs16 / cf32 / cf64 raw — the sample rate from the name like `rec_2Msps.cu8` or from *sample rate of raw IQ files* —, SigMF, WAV IQ; from Files) is sent to the **`iq`** output from the clip start (plus `off`) at its real sample rate × speed, the first IQ clip under the playhead wins. Video clips: their sound is mixed, the picture is not shown. Files are decoded in memory (up to about 40 M samples of audio, an audio file up to 200 MB); the readout shows how many are ready.
- **Markers**: **M** — a marker at the playhead (or the view centre), click the flag on the ruler — go there, drag — move, double click — rename, Delete — remove; they are kept in the patch. The `marks` input shows external markers (rows with a time and `label` / `text` / `name`, another colour); the `marks` output gives the own markers (`label`, `t` — s on the axis, `abs` — absolute time in seconds), `mark` — a record when the playhead passes a marker.
- **Live events** without a Table: the `rec` input appends records (an `t` stamp is added when the record has no time column) and the `gate` input turns a signal into events — a rising edge over *gate threshold* starts an event, a falling edge ends it (lane *lane of gate events*, time = the computer's clock in ms, `dur` in ms); they join the rows of the Table (so with a Table in seconds from the start the live events lie far away: use a Table with absolute time or only live events). *live events kept* limits the buffer, *Clear live events* empties it. With *follow the end* the view follows.
- **Export**: *Export PNG* saves the picture of the timeline (lanes, markers, selection).
- **Outputs**: `rows` (the selected events as the original rows), `stats` (one row per lane: `lane n t0 t1 span dur… duty rate period… idle ok miss jitter rssi lag…`, seconds; wire it to a Table with key `lane` and *rows in = sync*, or to Table Chart), `edited`, `diff`, `marks`, `mark`, `audio`, `iq`, `rec`, `file`, `on` (events under the playhead), `t`, and for the selection `count`, `period`, `dur`, `duty`, `hit`.
- Not there yet: effects other than gain / filters / echo on a lane, a picture of video clips, stereo mixing, creating a new lane by dragging below the last one (a new lane appears when a clip with a new lane value is added in the Table).

**Activity Events** (Analysis) feeds a Timeline from a spectrum: it takes a grid of channels (*first channel centre*, *step*, *channels*, *width*) from the `spec` of a USB SDR / FFT and turns channel activity into events. Each frame the common level of the band (the lower third of the channels) is subtracted, so an AGC / gain step or a wideband noise rise does not make every channel busy at once; the result is smoothed over *smoothing* ms. The floor of a channel is a low quantile of that level (learned fast during the first *learn* ms, then it follows the drift at *floor adaptation* dB/s and stays frozen while the channel is busy). A channel is busy when it is *busy above the floor* dB over it and free when it stays below *threshold − hysteresis* for *hold* ms (shorter pauses are bridged); events shorter than *shortest event* are dropped. *Channel level*: mean power of the channel band, or *peak* (the strongest bin — weak narrow carriers stand out more). The `rec` output gives one record per finished transmission — `t` (epoch ms), `dur` (ms), `freq` (MHz), `ch`, `rssi` (peak, dB), `avg`, `snr` — for a Table, which is the storage: Table → Timeline (lanes by `freq`). With a sweeping SDR the channels outside the current window are not observed and keep their state until the sweep comes back (the resolution is then one pass). Outputs `active` (channels busy now) and `count`. Check: `node tools/test-activity.mjs`.

Presets: *Timeline: Periods, Durations and Replies on the Air (Table)*, *Timeline: Clip Arranger (edit with the mouse, mix, markers)* (Table ↔ Timeline with write-back, mix to the sound card). *USB SDR: Channel Activity Timeline (PMR446)*: RTL-SDR → Activity Events (16 channels of 12.5 kHz) → Table → Timeline → Table with the results per channel (needs the hardware). Check of the kernel: `node tools/test-timeline.mjs`.

### Row Player

**Row Player** (Sources) plays the rows of a list one by one — to imitate a moving vehicle, step through frequencies, replay packets and calls, or send a beacon. Table stores and edits the list; Row Player only walks along it (`modules/rowplayer.js`, the stepping is `seqProcess` in `modules/sequencer.js`, `node tools/test-rowplayer.mjs`).

- **Rows come two ways.** Wire a [Table](data.md#table)'s `rows` (or any set of records) to `rows` — the filter, the sort and *newest first* of the table apply, and this is the only way for a list that lives in the patch (`@patch`). Or give a **reference to storage**: the `list` field (or a text on the `list` input, e.g. from Table's `list` output) names a list of the browser DB or a built-in `presets/…` one; the player reads it itself, so a long list is not copied along a wire, and it follows the edits of the list (a reread at most once a second). The wire overrides the input, the input overrides the field.
- **Advance** (`trig` always steps by one row as well): **rate** — rows/s (0 = only `trig`); **dwell** — each row is held for the seconds in its *dwell col* (frequency stepping: `freq,dwell`); **time** — rows come out at their own timestamps (column `t`, `time`, `timestamp`… ISO, epoch s/ms or `HH:MM:SS`), speed `time ×`; with absolute timestamps and a *Time Base* on `t` the rows follow that clock (set it back and the replay restarts); **distance** — the next row comes out when the path along `lat`/`lon` reaches it at the given `speed` (km/h, m/s or knots; a *speed col* overrides it per row). With *interpolate* the marker moves smoothly between points (*rows/s* = update rate). `dist`, `bearing`, `progress` describe the current leg. Only the fields of the chosen mode are shown.
- **Order**: sequential, ping-pong, **random**, **shuffle** (every row once, then again); *loop*, *first row* / *last row* range, the `row` input picks a row (1…N).
- **Outputs**: `rec`, `text` (the *text col*, or the whole row), `row`, `count`, `next` (a pulse per row), `done`, `dist`, `bearing`, `progress`, every column as its own port, and `mid` / `span` for rows with a frequency (`lo`/`hi` or `freq`). A set that grows while it plays (a log) keeps the position; another list starts over.
- **Table now only shows and selects.** A click on a row (or the `row` input) sends that row to Table's own `rec`, `text`, `row` and field outputs; *first row selected at start* (List settings) sends the first row once. Its `list` output (the name of the active list, empty for `@patch`) is the reference for Row Player. Old patches are converted when they are opened: a Table that played rows (an *advance* other than *rate*, *rows/s* above 0, a wire on `trig` / `t`, or on `done` / `dist` / `bearing` / `progress`) gets a Row Player under it with its playback settings, the `trig` / `t` / `row` inputs and the row outputs move to the player, and Table's `rows` is wired to the player.
- **Trigger Clock** (Control): `trig` pulse and `gate` window. Modes: *interval* (with *jitter* %), *random* (min…max), *poisson* (mean = interval), *schedule* (`08:00, 12:30:15, */15s, */5m` — time of day or every N s/m/h, UTC or local; uses `t` from Time Base when wired). *burst* + *gap*, *delay*, *max N*, `gate` width (a window of N s after every trigger), `reset` input. The pulse lasts one block with a gap of one block between pulses.
- **Trigger Clock, mode *cron*** (Control; the former Cron node): a schedule written like crontab — five fields *minute hour day month weekday* (`*`, `a`, `a-b`, `a-b/n`, `*/n`, comma lists, names `mon…`/`jan…`, 7 = Sunday, `@hourly` `@daily` `@weekly` `@monthly`); if both day-of-month and weekday are given either one fires, as in Vixie cron. Outputs `trig` (a one-block pulse), `gate` (high for *gate length* seconds after each firing — record 10 minutes every hour), `n` (firings), `next` (seconds to the next). Zone UTC or local; time comes from the `t` input (*Time Base*, so a sped-up virtual clock works) or the system clock. A firing missed by rewinding or by a sleeping tab (> 2 min) is not caught up. Wire `gate` into a recorder or `trig` into the *Spectrum Archive*
- **Spectrum Archive** (Output): writes spectra into the browser's IndexedDB (`dsp-spectra`), so a long unattended watch of a band survives a reload. Input `spec` from any spectrum source (RTL-SDR, FFT, IQ Spectrum, tinySA…). A row is the *mean power* (or *max hold*, for sporadic signals) of all frames inside the period, reduced to *bins per row* by taking the maximum of each group, stored as 8 bits at 0.5 dB steps below the row's peak (127 dB of range, about 1 KB per 1024-bin row). Modes: *periodic* (a row every period), *gate* (rows only while the `gate` input is high — wire a *Cron* `gate` here; what is left when it drops is written), *trigger* (on each rising edge of `trig`, e.g. a *Cron* `trig`, record the next period). A session is a run of rows on one frequency axis; changing the axis or **New session** starts another. **Export CSV** (time, one column per bin, dB) and **Export PNG waterfall** take the current session. The oldest rows beyond *rows kept* are dropped; **Clear all** empties the archive. Outputs `rows` (this session) and `total`. Time stamps are the computer's clock (UTC in the export); a browser may throttle a background tab, so for days-long runs keep it in the foreground or use a kiosk window
- **Time Base** (Control): virtual time — the system clock or a manually set start (UTC) with any speed; outputs `t` (epoch s), `iso`, `tod`; the `set` input takes a new time.
- **Stopwatch** (Control): measures the time between a `start` event and a `stop` event — delays, data transfer time, round trips. Inputs `start`, `stop`, `reset` take any wire: a number or a signal (an event is a rising edge through *threshold*; in a signal the crossing is found between samples, so the edge is placed to a fraction of a sample, so the resolution is finer than the 21 µs sample step at 48 kHz) or a text / record / bytes wire (every new value is an event). *Buttons* **Start / Stop** and **Reset** work by hand and are stamped at the click. *Clock*: **wall** — real time from `performance.now()` (0.1 ms in a normal page, 5 µs when the page is cross-origin isolated; a wire event is stamped when the block is processed, so it is as coarse as the block, a few ms), **samples** — the node's own sample count: exact and independent of CPU load, the right choice for delays inside a signal chain (a pulse through a filter, a delay or a loopback), but it does not see real-world waits. *Mode*: **start/stop** or **toggle** (every `start` edge flips). *Start while running*: ignore or restart. Outputs: `ms` (last measurement), `elapsed` (live, ms), `run`, `done` (a pulse), `text` (`12.345 ms`), `mean`, `n` and `rec` — one record per measurement `{n, start, end, ms, clock}`: in *wall* `start` / `end` are epoch ms with a fraction, in *samples* ms on the node's sample timeline. The readout keeps n / min / avg / max / σ (jitter). Logic: `modules/stopwatch-kernels.js`, `node tools/test-stopwatch.mjs`
