# Правила работы с репозиторием

## Обязательно

1. **Перед работой прочитай `docs/PROJECT_MAP.md`** — карта проекта: структура, точки входа, команды, подводные камни. Текущее состояние работы (что в работе, что проверено, с чего продолжать) — в `docs/HANDOFF.md`.
2. **Читай только файлы, относящиеся к задаче.** Поиск — через grep по символам; чтение — нужный диапазон строк, не файл целиком.
3. **Большие файлы не читать целиком**, если достаточно поиска по символам и диапазона строк (README ~120 строк, presets.js ~9700, core-graph.js ~3000, modules/* — сотни).
4. **Не сканировать** `vendor/` (десятки МБ wasm/моделей), `.git/`, сгенерированные файлы и большие логи без явной необходимости.
5. **Проверяй актуальность карты** (`docs/PROJECT_MAP.md`) по исходникам перед структурными изменениями — карта может отставать.
6. **После структурных изменений обнови затронутый раздел карты** (новые файлы, переезды, переименования).

## Запреты и обязательные процедуры

- Исходники — строго без npm-зависимостей; тесты — Node 22+ без установки пакетов (vm-based). Не добавляй зависимости.
- `*-kernels.js` — чистая логика без DOM: там же живут функции для тестов. DOM — только в обычных `modules/*.js`.
- **После правки любого файла из оболочки** (`index.html`, `styles.css`, `sw.js`, `help/*.md`, `core-*.js`, `modules/*`) запусти `node tools/stamp.mjs` — пересчитает версию для service worker.
- Новый JS-файл: добавить **в оба** места — массив `L` в `index.html` и `SHELL` в `sw.js` (порядок в `L` важен: kernels раньше модуля, `usb-bridge.js` раньше `webusb-serial.js`, `presets.js` и `modules/help.js` раньше `core-graph.js`).
- Карту `const H={...}` в `sw.js` **не править руками** — её генерирует `tools/stamp.mjs`.
- `help/modules.md` — генерируется (`node tools/gen-modref.mjs`, нужен playwright, в базовом окружении не установлен); не править руками.
- Голосовой/ручной push за пределами `main` без запроса у пользователя не делать.
